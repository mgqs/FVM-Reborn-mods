# 卡片 Mod 压缩包模板（不包含图片）

这是按当前项目 Mod API v1 制作的普通卡模板。
当前压缩包没有 PNG，不能直接通过导入校验。先补上自己的图片，再打包导入。
游戏需要包含 Lua 新接口的 FvmNativeSupport.dll；旧 DLL 无法运行本模板。
模板未在游戏中实测，本次没有编译游戏。

## 1. 解压，添加图片

在 card.json 同级新建 images 文件夹，放入下面五张 PNG：

```text
manifest.json
card.json
logic.lua
使用说明.md
images/
  icon.png          卡片图标
  card_01.png       卡片动画第1帧
  card_02.png       卡片动画第2帧
  bullet_01.png     子弹动画第1帧
  bullet_02.png     子弹动画第2帧
```

卡片动画内部的 PNG 尺寸必须一致，子弹动画内部也必须一致。
只有一张图片时，把 frames 改成只有一个路径；有更多帧时继续添加路径。
frames 数组的顺序就是动画播放顺序。
卡片动画使用 `"origin": "bottom_center"`，原点自动放在可见图案正下方的水平中心，排除透明留白。
同一动画采用所有帧可见范围的并集来固定原点，避免逐帧改变原点造成跳动。
子弹使用 `"origin": "center"`，原点自动放在 PNG 图片中心；背包、选卡图标与卡片动画使用相同的可见图案底部中心原点规则。
图片尺寸变化时不需要重新计算原点；发射位置通过 offset_x、offset_y 调整。
需要手动原点时可用 `"origin": "custom"`，并填写 origin_x、origin_y。旧配置的这两个数值仍然兼容。

## 2. 修改 JSON

JSON 不能写注释，也不能在最后一个字段后添加逗号。

| 字段 | 用途 |
| --- | --- |
| manifest.json 的 name | Mod 列表中的名称 |
| id | 唯一卡片 ID，例如 xiaoming.my_card；不能与其他卡片重复 |
| name、description | 卡片名称和描述 |
| hp、atk | 0–16 星的生命和攻击力；第1项对应0星 |
| cost | 放置花费 |
| cooldown | 选卡槽冷却，420帧为7秒 |
| cycle | 攻击间隔，120帧为2秒 |
| fps | 每秒播放多少张 PNG，允许1–60 |
| frames | 按顺序播放的图片路径 |
| origin_x、origin_y | 图片原点，单位为像素 |
| origin | bottom_center 为可见图案底部中心；center 为图片中心；custom 为手动坐标 |
| behavior_params.range_pixels | 本模板索敌距离，单位为像素 |
| behavior_params.bullet_speed | 本模板子弹每帧移动的像素数 |
| behavior_params.slow_ticks | 减速持续帧数，180帧为3秒 |
| behavior_params.offset_x、offset_y | 子弹相对卡片的发射位置 |

星级数值也可以写成一个数字，表示所有星级都相同。
例如把 hp 数组替换为 `"hp": 50`。
本模板用 range_pixels 索敌；顶层 range 是游戏卡片数值，不会自动换算为像素。

## 3. 金卡规则

普通卡用 `"is_gold": false`，数值数组需要17项（0–16星）。
金卡用 `"is_gold": true`，数值数组需要19项（0–18星）：
例如在 hp 数组末尾加 `135, 140`，在 atk 数组末尾加 `54, 56`。
单个数字形式不需要改数组长度。

合成屋最多强化到16星。17、18星必须是金卡，并且只能通过 Clotho 临时提升。
initial_unlock.level 最多16；不要用它配置17、18星。

## 4. 修改行为

logic.lua 的 on_create 在放置后初始化，on_step 在游戏每帧运行。
暂停时不运行。state 用于保存这张卡片的计时等状态。
伤害读取 ctx.atk，因此会随星级变化。
本模板不使用动画事件触发发射，卡片帧率与攻击间隔分别由 fps 和 cycle 控制。
不要使用文件读写、系统命令或 require，当前 Lua 接口不提供这些功能。

## 5. 重新打包和导入

子弹的 JSON 配置位于 `projectiles.ice`：

卡片 `target_type` 决定可攻击的敌人范围。子弹默认继承，`target_filter` 仅进一步缩小范围。模板已去掉子弹类型覆盖字段，修改卡片的 `target_type` 即可生效。`rotate` 和 `d_fruit` 包含空中、地鼠、隐形，但不包含潜水鼠；潜水鼠需 `throw`、`track` 或 `all`。

- `target_filter`：`ground` 地面、`air` 空中、`mole` 地鼠；`team` 为 `enemy` 敌人、`friendly` 友方、`all` 两者。`invincible: false` 跳过无敌目标。布尔阵营字段仅在未写 `team` 时生效。
- `hit.max_hits: 1` 命中一次销毁；`3` 可穿透三次；`0` 无限穿透。`repeat_hit` 控制同目标重复命中，`repeat_interval_ticks` 是间隔（60 为一秒）。`destroy_on_hit` 决定达到次数上限后是否销毁。
- `reflection.sources`：`cherry_pudding` 布丁、`water_god` 水神。空数组关闭反弹；`max_count` 是最大次数；`team: "keep"` 保留阵营。
- `enhancement.sources`：`brazier` 火盆、`jinniu` 金牛、`fire_god` 火神。空数组关闭增伤；按来源攻击倍率增强，`max_count` 限制次数，`clear_slow` 决定是否清除减速。当前仅倍率增伤，不自动转换火焰图像或添加溅射。

本模板开启三种增强来源、两种反弹来源。每个来源实例仅触发一次。高速碰撞自动开启，无需 JSON 配置；命中使用矩形碰撞盒，按路径先后顺序处理。卡片与子弹目标仍受逻辑行限制。

友方受伤使用卡片原有生命扣除和受击事件；敌方使用原有统一伤害事件。未添加图片的模板不能直接导入。

选中 manifest.json、card.json、logic.lua、images 文件夹及说明文件，压缩成 ZIP。
确认打开压缩包就能看到 manifest.json；允许有一层外目录，避免多层嵌套。
可以保留 .zip，或者把扩展名改成 .fvmmod。

在游戏设置中打开 Mod 界面，点击导入，选取补齐图片后的压缩包。
开启后重启游戏生效。不要直接导入这个尚未添加图片的原始模板。
导入后存放在 `%LOCALAPPDATA%\FVM_Reborn_makk\mod`。
关闭、删除后保留该 ID 的卡片进度；再次安装同 ID 后恢复。
