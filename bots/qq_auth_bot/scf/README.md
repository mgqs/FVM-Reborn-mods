# 云函数版（Webhook）部署说明

不需要开着电脑，也不需要买服务器。腾讯把「有人 @ 机器人」直接推到一个
HTTPS 地址上，这个地址是你的云函数；有人领码它才跑几百毫秒，没人领码它
不存在。

## 和 WebSocket 版的关系

**二选一，不能同时开。**

| | WebSocket 版（`bot.py`） | Webhook 版（本目录） |
|---|---|---|
| 怎么收消息 | 机器人主动连长连接 | 腾讯 POST 过来 |
| 需要什么 | 一台常开的机器 | 一个 HTTPS 地址 |
| 关电脑后 | 玩家领不到码 | 照常发码 |
| 账本 | `tools/qq_auth.db` | COS 上的 JSON |
| 适合 | 本地调试、测试改动 | 正式给玩家用 |

两边同时开会把同一条消息处理两遍（玩家收到两条一样的回复，账本被写两次）。
切过去之后本地就别再跑 `start_bot.bat` / `python bot.py` 了。

## 一、准备（约 15 分钟，只做一次）

### 1. 注册腾讯云

<https://cloud.tencent.com> 注册并完成**实名认证**。不实名开不了云函数。

### 2. 建一个对象存储桶（放账本）

控制台 → 对象存储 COS → 存储桶列表 → 创建存储桶：

| 项 | 填什么 |
|---|---|
| 名称 | 随便，如 `fvm-auth` |
| 地域 | 选离你近的，如 `ap-guangzhou`（**后面环境变量要填一致**） |
| 访问权限 | **私有读写**（默认就是，别改成公有） |

创建完记下**完整桶名**，形如 `fvm-auth-1250000000`，末尾那串是你的 APPID，
不能省略。

然后到这里拿密钥：控制台 → 访问管理 → API 密钥管理 → 新建密钥。
会得到 `SecretId` 和 `SecretKey`（`SecretKey` 只显示一次）。

> 建议单独建一个子账号，只给这个桶的读写权限，别直接用主账号密钥。
> 密钥泄露等于别人能改你的账本。

## 二、打包

```bash
cd bots/qq_auth_bot/scf
python build.py
```

产出 `bots/qq_auth_bot/scf-qqauth.zip`（约 37 KB）。

这个包**不含** `app_secret` 和 `auth_secret.txt`——密钥走环境变量，
免得留在代码包的构建历史里。

## 三、建云函数

控制台 → 云函数 SCF → 函数服务 → 新建：

| 项 | 填什么 |
|---|---|
| 创建方式 | 从头开始 |
| 函数类型 | **事件函数**（不要选 Web 函数） |
| 函数名称 | `qqauth-bot` |
| 运行环境 | **Python 3.9** 或 3.10 |
| 提交方法 | 本地上传 zip 包 → 选刚生成的 zip |
| 执行方法 | `main.main_handler` |
| 内存 | 128 MB 够用 |
| 超时时间 | **10 秒**（默认 3 秒偏紧，改大一点）。巡检那一轮要发最多 20 条消息，慢的话给到 **30 秒** |

### 环境变量（函数配置 → 环境变量）

| 变量 | 值 | 必填 |
|---|---|---|
| `QQ_APP_ID` | `1906122973` | ✅ |
| `QQ_APP_SECRET` | 开放平台的 AppSecret | ✅ |
| `AUTH_SECRET` | `tools/auth_secret.txt` 里的那 40 位 | ✅ |
| `COS_SECRET_ID` | 上面拿的 SecretId | ✅ |
| `COS_SECRET_KEY` | 上面拿的 SecretKey | ✅ |
| `COS_REGION` | `ap-guangzhou`（和你建桶时选的一致） | ✅ |
| `COS_BUCKET` | `fvm-auth-1250000000`（**带 APPID 后缀**） | ✅ |
| `COS_KEY` | `qqauth/ledger.json` | 可省 |
| `MAX_DEVICES` | `2` | 可省 |
| `AUTH_ADMIN_TOKEN` | `bots/qq_auth_bot/config.json` 里的 `admin_token` | 想要 `/解绑` 就必填 |
| `ADMIN_QQ` | `1017443780` | 可省，仅用于文案 |

群成员清理相关的变量（不填就按下面默认值走，**第一次务必保持 `dry_run`**）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `GROUP_OPENID` | 空 | **必填**。你的群 openid。不填则巡检直接退出，什么都不做 |
| `KICK_MODE` | `dry_run` | `dry_run` 只算不动手；`mute` 只禁言；`remove` 真踢人 |
| `KICK_NO_AUTH_DAYS` | `3` | 入群多少天还没绑授权码就清 |
| `KICK_IDLE_DAYS` | `7` | 多少天没说话就清（**已绑定的人也照此清理**） |
| `KICK_BOUND_IDLE` | `1` | 改成 `0` 表示已绑定的人永不因「不发言」被清 |
| `WARN_BEFORE_SEC` | `3600` | 到点前多少秒先 @ 提示一次（1 小时） |
| `EXEMPT_MARKS` | `留` | 昵称**包含**这个字就不清。多个用逗号分隔 |
| `EXEMPT_OPENIDS` | 空 | 手动写死豁免的 member_openid，逗号分隔 |
| `BLACKLIST_EXPIRE_DAYS` | `0` | 黑名单多久自动解除；`0` = 永久 |
| `PUSH_QQ_BLACKLIST` | `0` | 踢完是否顺带调官方群黑名单接口。**该接口在内邀（11253）**，开了失败也只记日志 |
| `COS_MEMBERS_KEY` | `qqauth/members.json` | 成员表在 COS 上的位置，和 `ledger.json` 分开存 |

`GROUP_OPENID` 从哪来：群里 @ 机器人发一条消息，云函数日志里那行
`[scf] 群@ xxx group=8A3B2C1D...`，`group=` 后面就是。原样填，别加引号。

`AUTH_SECRET` 的值可以直接这样取：

```bash
cat tools/auth_secret.txt
```

**填错的后果**：能正常保存回调地址、能收到消息，但发出去的码游戏端
一律验不过。启动日志里会看到「授权密钥指纹」，和 `--check` 打出来的对一下
就知道有没有填错。

### 开一个公网 HTTPS 地址

函数详情页 → **函数 URL**（有的控制台叫「触发器 → 函数 URL」）→ 启用：

- 鉴权方式：**免鉴权**（必须！否则腾讯的请求会被 SCF 自己挡下来，返回 401）
- 记下生成的地址，形如 `https://xxx.ap-guangzhou.tencentscf.com`

**这个地址就是回调地址，整串填到开放平台，不要加路径、不要加斜杠。**

## 四、切到 Webhook

QQ 开放平台 → 你的机器人 → 开发设置 → **事件订阅与回调地址**：

1. 连接方式选 **Webhook**
2. 请求地址填上面那个函数 URL
3. 事件订阅里**勾上「群聊 @ 机器人消息」和「单聊消息」**（不勾就收不到）
4. 保存

保存时平台会立刻发一次 `op=13` 校验请求。此时：

- 云函数日志里应出现 `[scf] 握手校验已应答`
- 开放平台页面提示保存成功

如果提示「签名校验不通过」，几乎一定是 `QQ_APP_SECRET` 填错或没生效
（改完环境变量要点「保存」，函数要重新部署一次才生效）。

## 六、排错

| 现象 | 原因 | 怎么办 |
|---|---|---|
| **浏览器打开函数 URL 报 `ERR_INVALID_RESPONSE`**，但 curl 正常 | 响应里出现**重复的 Content-Type**：函数 URL 的「参数兼容模式」网关会自己补一个，代码再设一个就是两个。curl 容忍，Chrome 严格拒绝 | 两件事都做：① 函数 URL 编辑里**取消勾选「参数兼容」**；② 代码里不要手写 `headers.Content-Type`（`main.py` 的 `_resp()` 已经去掉了） |
| 保存回调地址提示「签名校验不通过」 | AppSecret 错 / 环境变量没生效 | 改环境变量后重新部署；核对 `QQ_APP_SECRET` |
| 保存成功，但 @ 之后毫无反应 | 事件没勾选 | 开放平台里把「群聊@消息」「单聊消息」勾上 |
| 保存成功，但函数日志里一条请求都没有 | 函数 URL 鉴权没设成「免鉴权」 | 改成免鉴权，或检查 URL 是否填错 |
| 日志里出现「验签失败诊断」且 body 带中文乱码 | body 被中间层用错字符集解码过 | `_raw_candidates()` 会依次试 utf-8 / latin-1 / base64。三种都失败说明 AppSecret 真的不对，不是编码问题 |
| 回复 401/403 | 群未授权 / 机器人未上线 | 检查服务范围、群是否已添加 |
| 回「机器人还没配置好」 | `AUTH_SECRET` 没配 | 填上，重新部署 |
| 回「发码出错了」 | COS 读写失败 | 看日志里的具体报错，多数是桶名少了 APPID 后缀或 region 不一致 |
| 每个玩家每次都拿到新码、能无限领 | 账本没持久化 | 说明还在用本地文件，检查 `COS_*` 四项是否都配了 |
| 玩家收到**两条**一样的回复 | 本地 `bot.py` 还开着 | 关掉本地的 WS 版，只能留一个 |

> **用浏览器验证函数 URL 的预期结果**：应看到一行纯文本
> `FVM auth bot is running. QQ platform POSTs signed events here.`
> 这只是健康检查。如果你用 curl 发 POST 但没带签名，会得到 401 `{"error":"invalid signature"}`——两种都说明函数是活的。

## 八、群成员自动清理（定时巡检）

### 8.1 它会做什么

群里每进来一个人，机器人记一笔 `join_ts`。之后每 15 分钟巡检一次：

1. **入群 3 天还没领授权码** → 到点前 1 小时先 @ 他提示一次，到点还没领就清出去；
2. **7 天没在群里说过话** → 同样先提示再清（已绑定的人也照此清理，可用
   `KICK_BOUND_IDLE=0` 关掉这条）；
3. 被清出去的进黑名单（默认永久）。

**只要昵称里带「留」字，就永不被清。** 这是给人留的后门，不是 bug。

黑名单记在 `member_openid` 上，改名不影响；想放人出来用 `/解黑 <openid前缀或昵称>`。

### 8.2 三个安全阀

| 阀 | 作用 |
|---|---|
| `KICK_MODE=dry_run`（默认） | 只算、只发警告、只写审计，**一个人都不动**。先跑几天看日志，确认名单没错再切 |
| 巡检每轮最多处理 20 人 | 平台主动消息频控 20 条/分钟。人多就多跑几轮，不会一口气刷屏 |
| 踢人失败自动退化成禁言 | 平台「批量移出群成员」目前是内邀制（错误码 11253）。踢不动就禁言 30 天，**并且不进黑名单**——人还在群里，改名或发言都能自救 |

### 8.3 装定时触发器

云函数 → 函数详情 → **触发器管理** → 创建触发器：

| 项 | 填什么 |
|---|---|
| 触发方式 | 定时触发 |
| 触发周期 | 自定义 / Cron |
| Cron | `0 */15 * * * * *`（每 15 分钟。**SCF 的 Cron 是 7 段，开头多一个「秒」**） |
| 附加信息 | 留空 |

执行方法**不用改**（还是 `main.main_handler`）：`main_handler` 开头会认
`event["Type"] == "Timer"` 并把整轮巡检转给 `sweep_handler`，所以定时事件
不会被拿去验签、也不会刷 401 日志。想单独指到 `main.sweep_handler` 也行，
两个入口都通。

### 8.4 手动跑一轮（不用等定时）

浏览器打开：

```
函数URL?action=sweep&mode=dry_run     # 只看名单，不动手
函数URL?action=sweep&mode=remove      # 真踢
函数URL?action=sweep&mode=mute        # 只禁言
```

返回一段 JSON，形如
`{"mode":"remove","warned":0,"kicked":2,"muted":0,"skip":5,"failed":0,"round":3}`。

`skip` 是被豁免掉的人数（含「留」、群主/管理员、手动豁免、已退群）。

### 8.5 上线顺序（照着做，别跳）

```
① 填 GROUP_OPENID → 保持 KICK_MODE=dry_run → 部署
② 群里 @ 机器人发 /待清理，看名单对不对
③ 浏览器跑 函数URL?action=sweep&mode=dry_run，看返回的 JSON
④ 连着看两三天日志，确认没有该留的被列进来
⑤ 改成 KICK_MODE=remove → 保存 → 重新部署 → 跑一次 ?action=sweep&mode=remove
⑥ 返回里 muted 不为 0 就说明踢人接口还没给你开放，先接受禁言
```

### 8.6 已知的边界

- **机器人上线前就在群里的老成员不会触发入群事件**，所以「3 天未绑定」对他们
  永远不成立。他们只在第一次发言时被补登记（状态 `joined_late`），之后才进入
  7 天未发言的判定。
- 入群事件里**只有 openid，没有昵称**。昵称要等他第一次说话才拿得到，在那之前
  「含留豁免」对他是失效的——不过那时他连 3 天都没到，不会被清。
- 群昵称和 QQ 昵称在事件里是同一个 `username` 字段，代码无法区分谁设的。不影响
  判定：只要那个字段里有「留」字就放过。
- 踢人依赖内邀接口。真要立刻踢，手动在群里点「移出群聊」，或用 30 天禁言顶住。

### 8.6.1 群黑名单：两条路，只有一条通

平台有两个不一样的东西，别混：

**① 我们自己那份黑名单**（`members.json` 的 `blacklist`）——**一直在生效**。
踢人的同一轮就写进去，`/解黑` 也是改它。它只影响「这个人重新入群后下一轮会不会再被清」，
不影响 QQ 侧。

**② QQ 侧的群黑名单**（`POST /v2/groups/{gid}/member_blacklist`）——**在内邀（11253）**。
而且官方文档有一条硬约束：**只有在目标用户不在群中时才能加入群黑名单**。所以顺序
只能是「先踢出去 → 再拉黑」，人在群里调 add 会直接进 `fail_openids`。

开关是 `PUSH_QQ_BLACKLIST`（默认 `0`）。踢成功之后才调，失败只记一行日志，
不影响我们自己的黑名单。

**唯一不需要内邀就能拉黑的途径**：入群申请审批
`POST /v2/groups/{gid}/approval_join_request/{member_openid}`，机器人是群管理员就能用，
`op=decline` 时带 `add_to_member_blacklist: true`，平台顺手把人拉黑。所以如果你把群的
「加群方式」设成**需要管理员同意**，拒人的时候勾上「同时加入黑名单」，这条路现在就通。
`bot.py` 里已经封好了：`approve_join_request(gid, mid, op="decline", add_to_blacklist=True)`。

### 8.7 相关命令

| 命令 | 谁能用 | 作用 |
|---|---|---|
| `/绑定数量` | 仅管理员（私聊） | 只回一个数字，比如「绑定数量：12 台」。旧的 `/绑定列表` 保留为别名，同样只回数字 |
| `/待清理` | 仅管理员 | 列出当前该清的名单和原因，不动手（只看警告窗口+已到点） |
| `/查询 [小时]` | 仅管理员 | 列出 N 小时内会被清的人，按剩余时间从少到多排。不带参数看 24 小时 |
| `/豁免 <openid前缀或昵称>` | 仅管理员 | 手动让某人永不被清 |
| `/豁免`（不带参数） | **任何人，群里也能用** | 查自己有没有豁免、还剩多久被清、怎么拿到豁免 |
| `/解黑 <openid前缀或昵称>` | 仅管理员 | 把黑名单里的人放出来 |

`/查询` 和 `/待清理` 的差别：`/待清理` 只看「已经进警告窗口（默认剩 1 小时）+ 已到点」，`/查询 24` 看「从现在起 24 小时内任何时刻会到点」——那批人还没开始被告警，但你今天之内就会失去他们。想提前决定要不要 `/豁免`，用 `/查询`。

```
/查询          → 24 小时内会被清理：2 人
                 1. 5D253F99  老王  未绑定 · 已到点 · no_auth
                 2. 8A1B2C3D  小李  未发言 · 剩 4 小时 · idle
/查询 168      → 看一周内的
```

#### 玩家自查：`@机器人 /豁免`

这是**唯一**在群里放行的管理命令，因为不带参数时它只读成员表、只回发起人自己的状态，
不泄露任何别人的信息。玩家不必等到清理前 1 小时的警告才知道自己的处境。

```
@机器人 /豁免
```

有豁免：

```
你有豁免，不会被自动清理。
原因：你的群昵称里带了「留」字
```

没有豁免（顺带告诉他怎么自救）：

```
你目前没有豁免。
按现在的规则，你还没绑定授权码，2 天后会被清理。

三种拿到豁免的办法，任选一种：
1）把群昵称改成带「留」字的，改完下一轮巡检就生效
2）在群里说一句话（每次发言都会重置「7 天未发言」的倒计时）
3）找管理员，让他私聊发：/豁免 5D253F99
```

防线没有被顺手放开——`/豁免 <别人>`、`/解绑`、`/绑定数量` 在群里依然全部忽略，
自检第 ⑲ 节有专门的断言盯着这四条。

两个实现上的注意点：

- 回复**不带 URL**（平台以 `40054010` 拒收整条）。
- 群里每句话都会走 `members.touch_speak()` 记发言（`/豁免` 也一样），所以天天发一句
  `/豁免` 也能把 7 天倒计时顶住——它和「随便说句话」是同一条自救路径，只是顺带看到了状态。

## 九、管理侧操作

### 9.1 先认清一个限制：拿不到 QQ 号

QQ 官方机器人事件里**只有 `openid`，没有 QQ 号**，也没有任何接口能把 openid 换回 QQ 号。
所以「只有 QQ 1017443780 能解绑」这件事，没法直接用 QQ 号做判断。

用**一次性口令认领**落地，效果等价：

```
你（维护者）                管理员本人（QQ 1017443780）
     │                             │
     │  私下把口令发给他             │
     │ ──────────────────────────> │
     │                             │ 私聊机器人： /管理绑定 <口令>
     │                             │
     │      机器人把他的 openid 写进白名单，口令当场作废
     │                             │
     │      白名单非空后，任何人再发 /管理绑定 都被静默拒绝
     │                             │  ← 从此锁死在这一个账号上
```

口令在 `bots/qq_auth_bot/config.json` 的 `admin_token`（已生成好），
云端从环境变量 `AUTH_ADMIN_TOKEN` 读。**打包时会被剔除，不会进 zip。**

### 9.2 命令表（全部只在私聊生效）

| 命令 | 谁能用 | 作用 |
|---|---|---|
| `/我是谁` | 任何人 | 回自己的 openid，用来核对认领的是哪个身份 |
| `/管理绑定 <口令>` | 口令正确且尚无管理员 | 认领成为唯一管理员 |
| `/解绑 CF8A-EFFE` | 仅管理员 | 解绑单台机器（识别码） |
| `/解绑 ACEF3YL5` | 仅管理员 | 解绑单台机器（按码 ID，玩家报码时用） |
| `/解绑账号 5D253F99` | 仅管理员 | 解绑该 openid 名下全部机器（前缀匹配，需唯一） |
| `/绑定数量` | 仅管理员 | 回一个数字，如「绑定数量：12 台」。`/绑定列表` 保留为别名 |

**非管理员发这些命令，机器人一句话都不回。** 不是「无权限」，是完全静默 ——
回了就等于告诉全群有这条路。

**群里 @ 发这些命令一律忽略**，管理命令只在私聊生效。

每次解绑都会写进账本的 `audit` 字段（操作者 openid、目标、时间，保留最近 200 条）。

### 9.3 解绑之后会发生什么

- 该机器在账本里被删掉，**该账号的名额 -1**，可以重新领码；
- 但**他旧机器上的游戏仍然是已授权状态** —— 游戏端是纯离线验签，不会回连账本。
  真要彻底作废，得让他删掉 `%LOCALAPPDATA%\FVM_Reborn_makk\auth.dat`，或者换机。

### 9.4 兜底：直接改 COS（机器人不可用时）

控制台 → 对象存储 → 你的桶 → `qqauth/ledger.json` → 下载 → 删掉
`entries` 里对应 `hwid` 的那一条 → 上传覆盖。

或者本地配好 `COS_*` 后跑：

```bash
cd bots/qq_auth_bot/scf
python - <<'EOF'
import store
led = store.ledger_from_env()
rows = led.all()
print("共 %d 条" % len(rows))
for hwid, uid, code_id, code, ts in rows:
    print("%-10s %-24s %s" % (hwid, uid[:20], code_id))
print("已解绑 %d 台" % led.drop_hwid("CF8AEFFE"))
led.close()
EOF
```

⚠️ 改 `ledger.json` 时不要把 `admins` 字段删掉，那是管理员白名单，
删了等于把认领通道重新打开（口令还在，谁拿到口令谁就能认领）。

### 加码（池子发完时）

码池 `codes_pool.txt` 是**打进 zip 的快照**，云端直接读包内那份。所以本地 `poolgen` 加码后，**必须重新打包并上传部署**，否则云端仍按旧的包发，发完就回「授权码暂时发完了」。

```bash
cd bots/qq_auth_bot/scf
python ../../../tools/qq_auth.py poolgen 2000   # 追加 2000 个，自动避开已有 ID
python build.py                                 # 重新打包 ../scf-qqauth.zip
```

然后：云函数 → 函数代码 → 上传本地 zip → **点部署**。

两点放心：

- `poolgen` 是**追加**且会排除已有 ID，不会覆盖或重复，已发出去的码不受影响；
- 编号空间是 32⁸ ≈ **1.1 万亿**，加码只是改文件，不存在真正耗尽。

代价：换机器 / 重装系统 / 改计算机名都会消耗一个码（本机识别码变了就得发新码），所以码的消耗速度看**机器台数**，不是人数。

## 十、文件说明

| 文件 | 作用 |
|---|---|
| `main.py` | SCF 入口，解析 event 还原原始 body 后交给 webhook |
| `webhook.py` | 验签、op=13 握手、事件分发、发消息 |
| `ed25519_ref.py` | 纯标准库 Ed25519（含 RFC 8032 向量自检） |
| `store.py` | COS 账本 + 手写 COS 签名（不依赖 cos-python-sdk） |
| `members.py` | 群成员表（入群/发言/绑定/豁免/黑名单），独立存 COS |
| `sweep.py` | 定时巡检：算名单、发警告、踢人/禁言 |
| `build.py` | 打 zip |
| `selftest.py` | 端到端自检，模拟腾讯真实请求 |

四个自检入口：

```bash
python selftest.py        # 全链路（不联网），17 节
python main.py --check    # 配置 + COS 连通性
python main.py --simulate # 模拟一条群 @ 消息
python main.py --sweep    # 本地造 5 个假成员，验一遍清理判定
```
