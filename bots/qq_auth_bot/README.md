# FVM 授权机器人（QQ 官方机器人平台）

从 QQ 开放平台的机器人接收 `#授权 <本机识别码>`，从码池里发一个**绑定到那台机器**的码。

码里签了玩家机器的指纹，别人拿到也用不了——这是纯离线条件下唯一能做到「一码一机」的办法。

## 两种运行方式，二选一

| | 本目录（WebSocket） | `scf/`（Webhook 云函数） |
|---|---|---|
| 怎么收消息 | 程序主动连腾讯长连接 | 腾讯 POST 到一个 HTTPS 地址 |
| 需要什么 | **一台常开的电脑** | 一个云函数地址（免费额度） |
| 关掉电脑后 | 玩家领不到码 | **照常发码** |
| 账本 | `tools/qq_auth.db`（SQLite） | COS 上的 JSON |
| 用途 | 本地开发、改文案调试 | **正式给玩家用** |

两条都要 `config.json` 和同一份 `tools/auth_secret.txt`。**不要同时开**，
否则同一条消息会被处理两遍（玩家收到两条回复）。

云函数版的部署步骤见 [`scf/README.md`](scf/README.md)。

## 0. 先认清一件事：拿不到 QQ 号

官方平台的用户标识是 **openid**，不是 QQ 号。官方文档原话是「与真实的 ID 无关，请不要理解为真实的 ID」，而且不同机器人拿到的 openid 也不一样。

这不是 bug，是平台设计。所以：

| | NapCat 等第三方协议端 | QQ 官方机器人（本项目） |
|---|---|---|
| 身份标识 | 真实 QQ 号 | openid |
| 账号风险 | 有封禁风险 | 合规 |
| 需要服务器 | 否 | **否**（WS 长连接） |
| 能否显示「QQ：12345678」 | 能 | **不能** |

**openid 够用来防重复领取**：同一个 QQ 在这个机器人下永远是同一个 openid，腾讯侧给的、伪造不了。但**它做不了「一码一机」**——游戏端拿不到 openid，没法核对「这个码是不是我的」。

所以真正锁机器的因子是**本机识别码**（机器指纹），账本主键是它，openid 只作为「谁领的」记录在案。两者分工见 `docs/QQ号校验与授权方案.md` 12.1。

## 1. 拿 AppID / AppSecret

1. 打开 [QQ 开放平台](https://q.qq.com/)，用创建机器人的 QQ 登录
2. 进入你的机器人 → **开发管理** → **开发设置**
3. 复制 **AppID**，点生成 **AppSecret**（只显示一次，务必保存）

> AppSecret 泄露 = 别人能冒充你的机器人发消息。别贴群、别进仓库。

## 2. 装依赖

```bash
cd bots/qq_auth_bot
pip install -r requirements.txt
```

只有 `websockets` 一个依赖，HTTP 用标准库。

## 3. 生成码池

```bash
cd ../..            # 回到项目根目录
python tools/qq_auth.py poolgen 500
```

`tools/codes_pool.txt` 一行一个码 ID，可以自己改成好记的（`VIP0001`、`NEZHA88`），字符集限 `23456789ABCDEFGHJKLMNPQRSTUVWXYZ`（排掉 0/O/1/I，玩家不会看错）。**加码随时改这个文件，不用重发游戏。**

## 4. 填配置

编辑 `bots/qq_auth_bot/config.json`（已 gitignore，不会进公开仓库）：

```json
{
  "app_id": "1906122973",
  "app_secret": "在这里粘贴开放平台生成的 AppSecret",
  "sandbox": false,
  "auth_command": "#授权",
  "allow_group_issue": true
}
```

AppID 已经填好了，只需要贴 AppSecret。配置优先级：**环境变量 > config.json > 默认值**，所以想临时换号可以用 `set QQ_APP_SECRET=xxx` 覆盖。

## 5. 先验配置，再启动

```bat
python bots\qq_auth_bot\bot.py --check      # 只验密钥+网关+池子余量，不连 WS
python bots\qq_auth_bot\bot.py              # 正式连
```

`--check` 能打印出 access_token 和网关地址，就说明 AppID/AppSecret 对、网络通。**别跳过这步直接连**，不然报错分不清是密钥错还是网络问题。

启动后看到 `[ws] 机器人已在线，等待消息…` 就成了。

## 6. 玩家怎么用（重要）

**完整流程：**

```
① 游戏 → 右上角「授权」按钮 → 面板显示「本机识别码 1A2B-3C4D」，点一下复制
② 私聊或群里 @ 机器人：#授权 1A2B-3C4D
③ 机器人回码 → 粘贴进游戏 → 确认绑定
```

**`#授权` 不带识别码时机器人不会发码**，只回一段领取说明。这是刻意的：不带机器码的码任何人都能用，等于白做。

**群里 @ 也发码**（`allow_group_issue` 默认 `true`）。码已经锁死机器，公屏发也拿不走，只是不太雅观；想只走私聊改成 `false`。

发过的码不会丢：同一台机器再发 `#授权` 或 `#查码`，拿回的是**同一个码**，不消耗新的池子 ID。

**一个 QQ 最多绑 2 台机器**（`MAX_DEVICES_PER_UID`）。第 1 台、第 2 台正常发码；**第 3 台开始直接拒绝**，机器人只回「已经绑满 2 台，不能再领新码」，**不提供任何解绑/重领途径**——这是刻意的，避免玩家把限额当橡皮筋。换电脑 / 重装系统 / 改计算机名之后识别码会变，会占掉一个名额，所以两台要省着用（台式 + 笔记本刚好）。

## 7. 配置项

`config.json` 里全部可配，也都能用环境变量覆盖（同名大写，见下表）。

| config.json | 环境变量 | 默认 | 说明 |
|---|---|---|---|
| `app_id` | `QQ_APP_ID` | — | **必填**，开发设置里的 AppID |
| `app_secret` | `QQ_APP_SECRET` | — | **必填**，开发设置里的 AppSecret |
| `sandbox` | `QQ_SANDBOX` | `false` | `true` 走沙箱域名（未上架时用） |
| `auth_command` | `AUTH_COMMAND` | `#授权` | 触发命令 |
| `allow_group_issue` | `ALLOW_GROUP_ISSUE` | `true` | 群里 @ 是否也发码（码锁机器，发出去也拿不走） |
| — | `MAX_DEVICES` | `2` | 一个 QQ 最多绑几台机器，超了硬拒绝。一般别动 |

> `config.example.json` 是给别人的模板，`config.json` 是你自己的（含 Secret，已 gitignore）。

## 8. 官方平台的硬限制（必须知道）

这些是平台规则，代码绕不过去：

| 限制 | 影响 |
|---|---|
| **被动回复 5 分钟窗口** | 收到消息后必须立刻回，超时发不出去。脚本已是收到就回 |
| **一条消息最多 5 次回复** | 反复回同一个 msg_id 会失败，脚本用递增 `msg_seq` 规避 |
| **不支持主动推送** | 机器人不能主动找人；只能等玩家先发消息 |
| **个人主体不能公开使用** | 只能加自己是群主/管理员的群；私聊需在管理端「开发设置」里加**开发体验用户号码** |
| **沙箱环境拉不进群** | 2026-06 状态，需上架审核后才能进正式群 |

**个人主体这条路只能服务一个小圈子**（自己的群 + 白名单用户）。要放开给所有人，得企业主体 + 提审上架。这一点决定了你现在能服务的人数上限，不是代码问题。

## 9. 加不进群怎么办

**先明确一件事：这套功能不需要机器人进群。**

领码走的是 `#授权 <本机识别码>`，私聊或群里都行。玩家在手机 QQ 里 `联系人 → 机器人` 找到它就能私聊，跟群没有关系。群只是"人多的时候方便"，加不进去不影响发码。

如果确实要进群，按这个顺序排查（887959479 这类情况基本都在这四条里）：

| 检查项 | 说明 |
|---|---|
| **① 你是不是群主** | 个人主体（含未认证）**只能加到自己是群主的群**。管理员身份不行，群成员更不行。不是群主就转让，或者放弃进群 |
| **② 添加入口对不对** | 必须用**最新版手机 QQ**：`联系人 → 机器人 → 你的机器人 → 资料页底部「添加到群聊」`。在群设置里点"添加机器人"是另一套，找不到你的机器人 |
| **③ 管理端服务范围有没有开** | 开放平台 → 你的机器人 → **服务范围** → 把「QQ 群」打开并保存。没认证时只有管理员可用，认证后个人主体上限 500 个群 |
| **④ 加进去之后能不能收到 @** | 手机 QQ 群设置 → 机器人 → **机器人可获取的群聊消息范围** 设为「获取群内全部消息」。不改这个，@ 了也没反应 |

> 官方两个文档页现在的口径不一致：FAQ 页还写着「个人主体暂不支持公开使用」，新版产品介绍页已经改成「个人认证可设置为公开使用，进群上限 500」。说明能力在灰度放量。你按 ③ 去试，能不能开取决于账号被灰度到没有。

**如果 887959479 不是你的群**，个人主体这条路就走不通了。只有两个选择：认证企业主体（个体户也行），或者改回 NapCat 这类第三方协议端（能进任意群，但有封禁风险，代码要换回 OneBot 协议）。

**绕过去的办法**：用「开发设置 → 内部体验号码」加 20 个 QQ 号，这些号**不受服务范围限制**，可以直接私聊领码。小范围发码完全够用。

## 10. 出问题了看这里

| 现象 | 原因 |
|---|---|
| **启动后完全没反应，几秒就退出** | **九成是没装 `websockets`**。`ModuleNotFoundError` 被重连逻辑吞掉，看起来像"起来了但不动"。先跑 `python bot.py --check`，第一行就会告诉你 |
| `--check` 报 401 | AppID 和 AppSecret 不是同一个机器人 / Secret 重置过没更新 |
| 连上了但不回消息 | 没 @ 机器人；或该群没给机器人「获取全部消息」权限 |
| 报权限错误 | 功能没提审开通，个人主体常见 |
| 私聊没反应 | 你的 QQ 不在「开发体验用户号码」白名单里 |
| 分不清是没收到还是没回复 | `python bot.py --listen 120`，然后去 QQ 发消息。能打印 `[事件] C2C_MESSAGE_CREATE...` 就是收到了 |
| 回「授权码暂时发完了」 | 池子空了：`python tools/qq_auth.py poolgen 2000` 追加，然后**必须重新打包 zip 并上传部署**（云端读的是包内的 `codes_pool.txt` 快照，本地加码不会自动生效） |
| 回「已经绑满 2 台机器」 | 该 QQ 名额用完了，正常拒绝，**不是故障**。要做售后只能管理侧手工处理，机器人不给玩家解绑入口 |
| 群里 @ 了只回领取说明 | 正常，没带本机识别码 |
| 回「这个码是给另一台机器的」 | 游戏端提示，说明码和本机识别码不匹配，重新领 |
| 群里 @ 完全没反应 | 群设置里「机器人可获取的群聊消息范围」不是"全部消息" |
| 加不进群 | 见第 9 节，先确认你是不是群主 |
| 断线 | 脚本连续失败 5 次会停，不无限重连（避免被风控盯上）。查网络后再启动 |

## 11. 机器人挂了怎么办

它是单点。挂了玩家领不到码，所以留一条手工通道：

```bash
python tools/qq_auth.py issue <openid>
```

但 openid 不是玩家能报给你的东西（他看不到）。实操建议：让玩家把**游戏里的授权状态截图**发你，你按 `python tools/qq_auth.py ledger` 查有没有记录；新用户就直接 `python tools/qq_auth.py issue 手工_网名` 发一个码，账本照样记着。

群公告写清楚：「机器人不在线时私聊管理员领码」。别让玩家以为领不到就是没资格。
