# SWF 单卡行为适配工具

双击本目录的 `启动软件.cmd`。不需要编译游戏。本机使用已安装的 Python 和 JPEXS；换电脑需安装 Python 3，并在窗口选择 JPEXS 的 `ffdec-cli.exe` 和游戏的 Lua DLL。

## 使用

1. 选择 SWF、JPEXS、游戏 DLL 和结果目录。
2. 点击“提取全部脚本”，等待结束。不会只导出名字带 Attack 的类，也不会运行 SWF。
3. 打开结果目录，查看 `转换报告.md` 与 `scripts_inventory.json`。
4. 卡片入口类可留空自动识别；多个候选时填写 `card_dependencies.json` 中的完整入口类名。
5. 点击“严格转换为 Lua”。支持的行为输出单个 `logic.lua`，未支持行为明确报错。依赖及排除理由见 `card_dependencies.json`，适配规则与接口要求见 `card_adaptation.json`。

窗口会在后台工作，导出可能需要数分钟。每次提取都会新建目录，避免旧 Lua 混入新结果。

## 完整性检查

- 保存原 SWF 和解压 SWF，校验声明长度；FWS、CWS 已支持。ZWS 原文件保留，但需先解压。
- 递归保存所有标签，包括嵌套 MovieClip；记录偏移、帧号、父标签和 SHA-256。
- 独立解析所有 ABC，列出所有方法体，包括构造器、类初始化与脚本初始化；每个方法体另存原始二进制。
- JPEXS 分别导出全部源码和 P-code，遇到错误停止，禁止忽略错误。
- 用 JPEXS 的类目录核对源码，并核对原 ABC 类数；源文件、函数清单及无法转换原因全部记录。
- 按钮、剪辑、AS1/2 动作、外部导入、嵌入二进制均不能悄悄跳过。

保存原始数据可保证未转换的数据仍在；不能因此宣称反编译源码与原程序完全等价。该工具不声称能找回 SWF 中没有的外部游戏源码。

## 目前真正能自动转换的范围

支持单个无外部依赖的 AS3 行为类，含空构造器与 Mod API v1 回调：
`on_create`、`on_step`、`on_timer`、`on_animation_event`、`on_animation_end`、`on_destroy`。
参数为 `ctx:Object, state:Object`，返回 `void`。示例见 `示例行为.as`。

支持带类型的 Number/Boolean/String 局部变量、state 标量、ctx 数值属性、数值运算及比较、if/else、return、受支持的 Math 方法和当前游戏 api 对象调用。
数字采用 Lua 浮点数，避免 Lua 整数溢出与 AS Number 不一致。拒绝隐式类型转换、int/uint、未初始化状态、未知调用和未解析语句。

**这是可扩展的严格子集转换器，不是任意 AS3 / Flash 自动移植器。**
通用分析识别 `IResource.a_3932` 入口，追踪父类、导入和同包类引用，列出方法、调用名、静态初始化、帧脚本和动态加载标记。所有脚本保留，每个文件有依赖链或排除理由。

这是保守类级依赖分析，不是通用 AS3 方法级语义转换器。未知继承、复杂控制流、Flash 战场对象、Buff、动态加载等仍需转换后端或经过核对的适配器。没有后端时明确报错，不套用其他卡片逻辑。简单回调使用严格子集后端；已核对版本使用源版本校验的行为适配器。保存源码不代表所有行为已转换。

转换成功后，用实际 `FvmNativeSupport.dll` 验证 Lua 的语法与初始化。报告仍会注明行为等价未证明：正确性还需原游戏与新游戏的逐帧轨迹、伤害和边界条件对照。
输出仅为行为 `logic.lua`；图片、卡片数值和 card.json 仍由 Mod 作者填写。

## 你提供的 0x11700070.swf

它包含终极三线枪相关攻击类、子弹类、攻击父类和灼烧触发器等大量依赖。
已加入 `ff7e725d1803...` 版本的适配器：三行双发、8 tick 准备、2 tick 连发间隔、上下斜线转水平、非 Boss 灼烧、独立层叠加/到期。核对 SWF 和全部源文件哈希，不同版本拒绝套用。

状态 `lua_adapted_unverified` 表示 DLL 加载及命令轨迹测试通过，战场效果没有验证。原版地图、特殊 Buff、随机种子、护甲和坐标存在宿主差异，报告列出；不能声称完整等价。

### 把单个 Lua 放进 Mod

1. `card.json` 写 `"script": "logic.lua"`，生命、攻击、价格、冷却和技能间隔由 JSON 填写。
2. `projectiles.default` 配置自己的 PNG。使用其他名称时在 `behavior_params.projectile` 填该名称。
3. `cycle` 是 60-Hz 游戏帧；原版基础间隔 26 × 50ms 对应 78 帧。
4. `behavior_params.grade` 为原版转职等级，默认 0；可以直接填 `burn_power`。一转每层灼烧伤害 13，持续 21 个 100ms 效果 tick，在 tick 0/10/20 结算。
5. 可调整 `muzzle_y`（默认 -75）、`source_tick_seconds`（默认 0.05）、`source_bullet_speed`（默认 10）、`battle_seed` 和 `source_card_id`。

轨迹/灼烧接口已加入 GML 源码，扩展现有 `api.shoot` 字段，无新增 DLL 导出。本次没有构建游戏或 DLL；旧游戏可执行文件不识别这些新字段，需运行包含源码改动的版本。
