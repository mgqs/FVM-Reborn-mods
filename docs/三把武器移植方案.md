## 二、通用移植流程

### 2.1 精灵导入（每个精灵一次）

mod97 的精灵是 `spr_xxx/1.png 2.png ...` 平铺，本项目要求：

```
sprites/spr_xxx/
  ├─ <frameGuid>.png                          ← 根目录这份，IDE 读它
  ├─ layers/<frameGuid>/<layerGuid>.png       ← 引擎合成用，必须同步写
  └─ spr_xxx.yy                               ← sequence / tracks / keyframes 全要齐
```

**两条致命红线**（历史踩过）：
1. 帧 PNG 在磁盘存**两份**，只写 `layers/` 那份会显示红十字叉；
2. `.yy` 里 `sequence.tracks[0].keyframes.Keyframes` 必须是**非空数组**（正常每帧一条），空数组同样红叉。

**建议做法**：不要手写 `.yy`，用现成精灵（如 `spr_hades_scythe`）作模板，复制目录后替换 PNG + 改 `name` / `frames` 数组 / `sequence.length`，再在 IDE 里 `Ctrl+Shift+S` 覆盖保存一次让 IDE 重建元数据。

### 2.2 对象创建

`objects/<obj>/<obj>.yy` + 事件 `.gml` + `.yyp` 的 `resources` 加一条 + `folders` 里归到对应分组。

### 2.3 注册

| 位置 | 函数 | 用途 |
|---|---|---|
| `scripts/weapon_registry/weapon_registry.gml` | `register_weapon(id, struct)` | 武器主表 |
| 同上 | `register_gem(id, struct)` | 宝石表 |
| `scripts/weapons_init/weapons_init.gml` | 调用 `register_weapon` | **老武器系统**（17 把，含 poseidon 老版） |
| `scripts/mod_weapons_init/mod_weapons_init.gml` | 调用 `register_weapon` | **mod 武器系统**（7 把，含 gods_shield） |

> **注意两套系统并存**：`gods_shield` 在 mod 系统，`poseidon_dart_gun` 在老系统，`death_scythe` 该进哪套需要定（建议进 mod 系统，与 `hades_scythe` 同处 `super_weapon` 槽）。

### 2.4 商品入口

源 `shop_init.gml:295-318` 三条武器商品（各 `cost:"200000"`、`type:"weapon"`）+ L319-411 十二条宝石商品。本项目对应位置：

### 5.3 核心逻辑（必须原样搬）

**子弹 O 形轨迹**（`obj_death_scythe_bullet/Step_0.gml`）：

```gml
t += move_speed;                 // 源写 speed，项目必须改名
total_deg += move_speed;
if (total_deg >= 360) { instance_destroy(); exit; }
if (t >= 360) t -= 360;
var nx = (1 - dcos(t)) / 2;
x = start_x + 1100 * nx;
y = start_y - 644.28 * power(nx, 1.75) * dsin(t);
```

> 半径 1100、纵向系数 644.28、指数 1.75 —— 这三个数决定弹道形状，改一个就变形，**不要"优化"**。

**攻击节奏**（`obj_death_scythe/Step_0.gml`）：IDLE 循环 0..19，ATTACK 循环 20..35；`start_t=32`、`interval=6`，`for (i=0; i<bullet_amount; i++) if (t == start_t + i*interval) event_user(1)`；`attack_timer >= attack_anim*flash_speed` 收招，`cooldown = cycle`。

## 六、GML 适配清单（移植时必改）

| # | 源写法 | 项目要求 | 原因 |
|---|---|---|---|
| 1 | `speed = 2` | `move_speed = 2` | 项目把 `speed` 列为保留字红线（内置变量） |
| 2 | `enum UnknownEnum { Value_0 }`（每个文件末尾重复） | 删除，统一用 `CARD_STATE` | 重复定义会编译报错 |
| 3 | `hitted_enemy = ds_list_create()` | 按项目同类子弹习惯（多数字段是单值） | 项目 `hitted_enemy` 惯例为单值；保留 ds_list 需同时管销毁 |
| 4 | `get_gem_info(...).xxx[lv]` | 核对项目 `weapon_registry.gml` 的字段名 | 同名函数存在但结构体字段可能不同 |
| 5 | `instance_create_depth_define(...)` | 确认项目是否有此函数；没有则用 `instance_create_depth` + 逐个赋值 | 项目 `Other_11` 里都是 `instance_create_depth` |
| 6 | `with (obj_enemy_parent) { target_enemy = id }` | **改 `other.id`** | `with` 块内读自身字段是项目历史 bug 高发点 |
| 7 | 源 `obj_player_shield` 的 `gods_*` 分支 | 项目已存在，只改精灵名 | 不要整块覆盖，会丢项目自己的改动 |

**每次改完必跑** `python tools/gm_arity_check.py`（扫 ~6000 文件，检查参数个数不匹配 = GM1020）。

## 八、风险与回滚

| 风险 | 表现 | 处置 |
|---|---|---|
| **精灵红叉** | IDE 里显示红十字 | 检查 `layers/<guid>/<layerguid>.png` 是否同步写了；检查 `.yy` 的 `keyframes.Keyframes` 是否非空 |
| **存档不兼容** | 老存档里 poseidon 的 `attack_gem` 等级失效 | 在 `Create_0` 里加兼容：`if (get_gem_index("attack_gem") != -1) atk = ...` 作为 fallback 保留一段 |
| **`super_weapon` 槽冲突** | death_scythe 与 hades_scythe 抢同一槽位 | 确认 `slot` 机制是"互斥装备"还是"同名槽可多选"；若是互斥，需扩成 `super_weapon_1/2` |
| **数值失衡** | atk 200 / cycle 900 对当前 3.0.2.11 版本过强或过弱 | 先用源数值上线，再按 `docs/抽卡概率与卡池总表.md` 的平衡基线微调 |
| **`.yyp` 手改出错** | IDE 打不开项目 | 每次改 `.yyp` 前备份；只增不删；改完用 `python -c "import json;json.load(open('.yyp'))"` 验证 |
