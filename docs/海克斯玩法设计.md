> 三条本轮定下的实现铁律：
> 1. **数值通道必须「三处齐改」**：`hex_state` 字段 → `hex_apply_core` 解析分支 → 读取函数。少任何一处，词条会静默无效（`hex_apply_core` 不报错，只是不写字段）。
> 2. **需要坐标 / 实例上下文的加成不能塞进按 `card_id` 的倍率出口**（`hex_atk_mult_for_card` 只拿得到 id）。一律在 `with (obj_card_parent)` 里单独乘一次，参考「逆火」的 `hex_near_cycle_hit`。
> 3. **星级不能在实例层改 shape**：`obj_card_parent/Other_10` 每帧按卡面存档重建数据，会把改过的 shape 抹回原样。星级类词条一律折算成攻击 / 生命。

### v0.9.2「编译错误修复（GM1020 / GM1031）」

| 报错 | 原因 | 修法 |
|---|---|---|
| `GM1020 hex_enemy_scale 接受至少 2 个参数，但提供了 1 个` | v0.9 给函数加了必填的第二参 `_force_boss`，而普通鼠的三处调用只传 1 个。GML 新版编译器把少传参当**编译错误**，不像旧版那样补 `undefined` | 拆成两个入口：`hex_enemy_scale(_inst)`（普通鼠，自动按 `is_boss` 判口径）、`hex_enemy_scale_boss(_inst)`（BOSS 强制口径），实际落点合并到 `hex_enemy_scale_apply(_inst, _boss)`，口径只有一份 |
| `GM1031 名称 'pi' 是资产或常量，无法分配` | `hex_state` 里的字段名 `pi` 与 GML 内置常量 `pi`（3.14159…）撞名。**读**能读（解析成常量），**赋值**直接报错 | 字段改名 `pi_value`，全工程 14 处引用同步（`hex_core` / `hex_persist` / `hex_roll` / `obj_hex_hud/Draw_0`） |

> 两条通用规则：
> 1. 给脚本函数加参数一律**新增一个入口函数**，不要改已有函数的签名——GML 不会给漏传的参数兜 `undefined`，会在编译期直接报 GM1020。
> 2. 结构体字段名避开 GML 内置常量与函数名（`pi`、`x`、`y` 这类），读起来正常、写起来报 GM1031，很容易漏到运行时才发现。

### v0.9.1「放置锁与首抽状态解耦」

现象：拿到某条词条（如「悬浮厨房」）之后，卡槽能选中、鼠标跟着虚影，但点地面怎么都放不下去。

| 项 | 问题 | 修法 |
|---|---|---|
| 放置锁判定 | `hex_place_locked()` 只看 `first_done`。只要有任何一条路径把面板关掉却漏设这个标记，整局就再也放不了卡——而游戏并没有暂停，表现正是"能选中、放不下去" | 末尾补一道判定：`obj_hex_panel` 实例不存在就直接放行。锁的唯一理由是"首抽面板还开着、玩家还没选"，面板没了就不该锁 |
| 面板存在但暂停丢失 | 暂停菜单、拾取面板等外部逻辑会把 `global.is_paused` 改回 `false`，玩家能在没选牌时操作卡槽，而锁仍然生效 | `obj_hex_panel/Step_0` 每帧强制 `is_paused = true`（只在 `closing == 0` 的等待阶段） |
| 点到死牌 | 已叠满上限的牌被点到时只弹提示，既不置 `first_done`、面板也关不掉，玩家会以为"选了但没用" | 点选即视为首抽处理完（`first_done = true`），面板仍可用放弃按钮关闭 |
| 悬浮厨房的占格放行 | gridless 分支直接 `return true`，把底座（`target_card`）、玩家角色占格一起绕过了，需要底座的增幅卡会凭空叠在空地上 | 分支内补齐三条：同格不能重复放同一张卡、需要底座的卡必须踩到底座、玩家角色所在格不能放 |

> 一句话：**放置锁的唯一依据是"面板还开着"，不是"某个标记位"。** 标记位可以被任何一条异常路径漏设，面板实例不会。

| 表现 | 未定义 | 定义了暂停、三选一布局、银/金/彩三套视觉与音效规格 |
| 掉落 | 无 | 敌人死亡 0.5% 掉落「海克斯餐牌」，拾取即触发选择 |

## 1. 系统总览

> **v0.5 一句话前提**：下面这四层，**只在海克斯模式里存在**。经典 / 抽卡 / 欧皇 / 随机礼盒四种模式下，它们连对象都不创建——不是关掉，是不存在。

四层结构，各司其职：

```
第一层　羁绊（被动）   —— 你带了什么，就得到什么
第二层　海克斯（主动） —— 你选了什么，就改变什么
第三层　掉落（随机）   —— 老天给了什么，就接住什么
第四层　压迫（自动）   —— 你拿了多少，老鼠就强多少
```

- **羁绊**：纯增益，由卡组构成自动触发，是"构筑的地基"。
- **海克斯**：**同向交易**——要么"我方变强、老鼠也变强"，要么"我方变弱、老鼠变得更弱"。不存在"我方变强、老鼠变弱"这种单向白嫖，是"构筑的方向盘"。
- **掉落**：0.05% 的小概率惊喜，打破固节奏，是"构筑的变量"。
- **压迫**：不是选项，是**账单**。每拿一条海克斯，老鼠都会按固定公式变强一档，越到后期越难打；省下的选择不会退钱，只会更被动。这是 v0.3 的核心基调。

前三层决定你**有多强**，第四层决定这份强**够不够用**。

**压迫感的四个来源**（本版刻意做成叠加，而不是单点）：

| 来源 | 作用方式 | 玩家感受 |
|---|---|---|
| ① A 型自带敌强 | 每条加码词条的「老鼠侧」都是一次涨价 | 变强的同时对手也在变强 |
| ② 压迫指数 PI | 持有条数越多，老鼠属性线性上涨 | 越到后期越紧，且能看到数字在涨 |
| ③ 鼠潮 | PI 到阈值就往波次里塞精英鼠 | 画面上的压迫，直接看得见 |
| ④ 弃权/重随代价 | 想不选也要付 PI，想换牌要付火苗 | 没有"安全牌"，每一步都要算计 |

三者互不替代：羁绊决定下限，海克斯决定上限，掉落决定这局会不会出现"意外之喜"，压迫决定这份上限**能不能兑现**。

### 1.1 「仅海克斯模式生效」的范围定义（v0.5 定死）

**归零原则**：只要 `global.play_mode != 4`，海克斯系统**整体不存在**——不注册词条池、不抽牌、不掉落、不显示 HUD、不写存档，`hex_mult` 与 `pi_enemy_mult` 恒为 `1.0`，羁绊不计数。

| 维度 | 海克斯模式（4） | 经典 / 抽卡 / 欧皇 / 礼盒（0~3） |
|---|---|---|
| 词条抽取与三选一面板 | ✅ | ❌ 完全不触发 |
| 词条效果（`hex_mult`） | ✅ | ❌ 恒 1.0 |
| 压迫指数 PI 与鼠潮 | ✅ | ❌ 恒 0，不注入精英 |
| 羁绊计数与档位 | ✅ | ❌ 不计算，界面不显示 |
| 敌人掉落「海克斯餐牌」 | ✅ | ❌ 不参与掉落判定 |
| 通关写入 `hex_unlocked` | ✅ | ❌ 不写 |
| 「已有词条」按钮 | ✅ | ❌ 不创建 |
| 压力表 / 羁绊栏 HUD | ✅ | ❌ 不绘制 |

**在海克斯模式内部，则全关卡、全对象生效**——这是"全局"唯一正确的落点：

| 维度 | 含义 | 要避免的反例 |
|---|---|---|
| **全关卡** | 岛屿正关、困难关、魔塔、龙渊、浮空、海底、营地、跨服、活动关 | 魔塔里没有，理由是"魔塔有自己的奖励逻辑" |
| **全对象** | 卡片侧作用于所有 `obj_card_parent`（含召唤物、Mod 卡、转职形态）；老鼠侧作用于所有 `obj_enemy_parent`（含精英、BOSS、召唤鼠） | 只对本体卡生效，转职形态失效 |

**出口唯一**：

```
卡片最终攻击 = 基础 × 增幅(buff_multiplier) × 星级 × 地形 × 羁绊 × hex_mult
老鼠最终属性 = 关卡基础 × 难度系数 × pi_enemy_mult
BOSS 最终属性 = 关卡基础 × 难度系数(boss_X_hp_modify) × pi_enemy_mult（移速不乘）
```

BOSS 走的是 `obj_battle/Step_2.gml` 里的独立生成路径，**不在普通鼠的组波循环里**，所以必须单独挂 `hex_enemy_scale_boss(inst)`；它只吃血量与攻击，移速保持原值。

这三个新增值（`hex_mult` / `bond_mult` / `pi_enemy_mult`）在非海克斯模式下必须**恒等于 1.0**，而不是"不写值"或"跳过计算"。这是本节唯一要死记的一条：

> **用默认安全值兜底，不要用条件分支去跳过。** 分支漏写一处，就是一处"某个模式下伤害偏高 8%"的隐性 bug；而默认 1.0 漏写不了——因为它是初始值。

#### 1.1.1 明确不生效的例外（写死，避免歧义）

| 场景 | 原因 |
|---|---|
| 教学关 / 剧情演示 | 固定走位，词条会破坏教学节奏 |
| 结算动画期间的伤害判定 | 已停止结算，避免"通关后还被炸死" |
| Mod 作者的调试开关 `debug_hex_off` | 方便逐卡测试，不影响正常玩家 |

### 1.2 海克斯模式的唯一一套参数

因为系统只在海克斯模式下存在，v0.4 里"默认档 / 高压档"两套参数被合并为一套。不再有"其它模式用 12 条""掉落 0.5%"这类说法。

| 参数 | 值 | 备注 |
|---|---:|---|
| 单局词条上限 | **16 条** | 2 波关靠掉落也难到 16，实际是魔塔 / 龙渊的天花板 |
| 开局首抽 | **必出彩** | PI 起步即 3 |
| 敌人掉落率 | **0.05%** | 见 3.1 掉落细则 |
| PI 斜率 | **0.8% / 点** | 上限 +30%（PI 37.5 触顶） |
| C 型占比 | 8% ~ 24% | 随难度与选择次数上升（3.4） |
| C 型单局上限 | 4 条 | 3.6 |
| PI 清零 | 岛屿单关清零；魔塔 / 龙渊 / 浮空 / 海底整条序列累积 | 3.7.6 |

> 16 条满配时 PI ≈ 32（混搭）~48（全彩），会直接踩到"BOSS 波加护卫 + 精英血量 +50%"的顶档。海克斯模式本质是**用更高的压迫换更高的构筑上限**，适合已经通关一遍的老玩家。

#### 1.2.1 隔离的实现方式：一个总开关 + 一个参数表

**禁止**在业务代码里散写 `if (global.play_mode == 4)`。所有判定集中到两个函数：

```gml
/// @function hex_enabled()
/// @desc 海克斯系统总开关。全工程唯一判定点，任何挂载点先过这一步
function hex_enabled() {
    return (global.play_mode == 4);
}

/// @function hex_cfg()
/// @desc 参数唯一来源。只有一套值，调数值只改这里
function hex_cfg() {
    return {
        max_hex:          16,
        first_pick_color: true,
        drop_rate:        0.010,
        pi_rate:          0.008,
        max_c:            4
    };
}
```

所有读取点统一改造：

| 读取点 | 原写法 | 改为 |
|---|---|---|
| 波次触发 | `if (current_wave % 2 == 0)` | `if (hex_enabled() && current_wave % 2 == 0)` |
| 上限判定 | `if (picks >= 12)` | `if (picks >= hex_cfg().max_hex)`（能走到这行说明已开启，不必再判） |
| 开局首抽 | `if (play_mode == 3)` | `if (hex_cfg().first_pick_color)` |
| 掉落判定 | `random(1) < 0.0005`（每秒每杀一只掷一次） | `if (hex_enabled() && random(1) < hex_cfg().drop_rate)` |
| PI 倍率 | `min(1 + _p * 0.008, 1.30)` | `hex_enabled() ? min(1 + _p * hex_cfg().pi_rate, 1.30) : 1.0` |
| 羁绊重算 | `bond_recalc()` | 函数首行 `if (!hex_enabled()) { global.bond_count = {}; global.bond_mult = 1.0; return; }` |
| 词条面板入口 | 无条件创建按钮 | `if (hex_enabled()) instance_create_depth(...)` |

另有一条配套约束：`obj_game_init` 里必须按模式把三个乘区初始化为 `1.0`，**不要留 `undefined`**。`undefined * 1.2` 在 GML 里会静默变成 `0`，表现为"整个模式的卡片不造成伤害"——这类 bug 极难定位。

#### 1.2.2 切换模式 = 本局作废（v0.5 简化）

模式只能在设置页切换（对局中不可改），所以不需要 v0.4 那套"超限灰显"的复杂逻辑，直接清空：

| 场景 | 行为 |
|---|---|
| 进入海克斯模式 | `hex_run_reset()`，从零开始；开局首抽必出彩 |
| 离开海克斯模式 | `hex_run_reset()`，本局词条 / PI / 羁绊全部清零，**不写档** |
| 已解锁的 `hex_unlocked` | **保留，不删**。它是终身藏品，与"本局"无关 |
| 藏品在非海克斯模式下的可见性 | 入口按钮不创建，玩家看不到（见 5.5.1） |

> 注意区分两个概念：**「本局词条」是临时的**（离开模式、退出、失败都清空）；**「已解锁词条」是终身藏品**（只增不减，且不提供任何数值加成，见 7 护栏）。

#### 1.2.3 新增海克斯模式的工程改动

本作没有独立的"模式按钮"，玩法模式是设置页里的互斥开关（`obj_config_menu/Step_0.gml` 的 `obj_setting_toggle`，`config_key = play_mode_gacha / lucky / gift`），取值 `global.play_mode` 0~3。新增第 5 档需要动 **5 处**：

| 位置 | 改动 |
|---|---|
| `objects/obj_game_init/Create_0.gml:155` | `clamp(global.play_mode, 0, 3)` → `0, 4` |
| `objects/obj_setting_toggle/Create_0.gml` | 增加 `if (config_key == "play_mode_hex") state = (global.play_mode == 4);` |
| `objects/obj_setting_toggle/Mouse_4.gml` | 增加互斥分支（开启海克斯模式时关掉抽卡 / 欧皇 / 礼盒，反之亦然）；切换时调 `hex_run_reset()` |
| `scripts/difficulty_rules/difficulty_rules.gml:125-127` | 模式文案加一支 `else if (global.play_mode == 4) result += "·海克斯";` |
| `objects/obj_config_menu/Step_0.gml` | 「已有词条」按钮只在 `hex_enabled()` 时创建（5.5.1） |

## 2. 羁绊系统

### 2.1 为什么本作需要羁绊

现有 12 大类分类体系此前只用于「增幅卡的作用目标判定」，玩家几乎感知不到它的存在。把它升级为羁绊后：

- 玩家开始主动凑分类，而不是无脑堆最强单卡；
- 卡池的 517 个形态第一次有了"流派"意义；
- 海克斯有了可以挂钩的对象（改阈值、改计数、改效果）。

### 2.2 计数规则（核心）

| 规则 | 说明 |
|---|---|
| **只按不同 `card_id` 计数** | 同一张卡放 3 张只算 1 个计数（关键，避免铺满同名卡刷羁绊） |
| **转职形态不额外计数** | 本体 / 一转 / 二转 视为同一张卡 |
| **召唤物不计入** | 由卡片生成的小怪、子弹、分身一律不算 |
| **实时重算** | 放置、铲除、被吃掉、复活都触发重算 |
| **可同时计入大羁绊与子羁绊** | 一张"小笼包"既算直射类，也算传统直线类 |
| **同名卡换形态不重复** | 转职后仍只占 1 个计数 |

> 这条规则是本系统与「铺卡」玩法的分界线：**想要高羁绊，就必须带更多种类的卡**，卡组宽度第一次变成有价值的资源。

**生效范围**：羁绊只在海克斯模式内计算与显示。其它模式下 `bond_recalc()` 直接返回、`global.bond_mult` 恒 1.0、左侧羁绊栏不绘制（见 1.1）。

阈值按各分类的卡片池大小分级：大池 2/4/6，中池 2/3/5，小池 2/3/4。

| # | 羁绊 | 池 | 阈值 | 2 档 | 3 档 | 4 档 |
|---:|---|---|---:|---|---|---|
| 1 | **直射类** | 31 | 2/4/6 | 直射类攻击 +8% | 直射子弹 12% 概率穿透额外 1 个目标 | 直射类攻击间隔 −14%，击杀老鼠 5% 概率 +5 火苗 |
| 2 | **投掷类** | 15 | 2/3/5 | 投掷溅射范围 +10% | 命中目标受到的下次伤害 +10% | 投掷可越过障碍，对空中伤害 +25% |
| 3 | **多向类** | 7 | 2/3/4 | 每个方向伤害 +10% | 每 3 次攻击追加 1 次补射 | 攻击范围 +1 圈，对同一目标连续命中最多叠 3 层 +5% |

### 2.4 子羁绊（小分类专精，8 条）

阈值更低、效果更专，只强化该小分类本身。与主羁绊**叠加**是刻意设计——大类给"势力"通用收益，小类给"流派"专属收益。

| # | 子羁绊 | 池 | 阈值 | 效果 |
|---:|---|---|---:|---|
| 1 | **传统直线类** | 13 | 2/4/6 | +10% 攻速／额外 1 次穿透／每 5 次攻击追加一发 |
| 2 | **固定轨迹类** | 6 | 2/3/4 | 轨迹伤害 +15%／轨迹数量 +1（若有）／受增幅倍率 +30% |
| 3 | **单线投手** | 9 | 2/3/5 | 单体伤害 +12%／溅射 +1 格／对精英伤害 +30% |
| 4 | **灼烧投手** | 3 | 2/3 | 灼烧概率 +10%／灼烧可叠 2 层 |
| 5 | **海星类** | 3 | 2/3 | 全方位伤害 +10%／每次攻击多 1 个方向 |
| 6 | **子弹增幅类** | 5 | 2/3 | 被增幅子弹伤害 +12%／被增幅子弹附带点燃 |
| 7 | **水管类** | 3 | 2/3 | 攻速 +12%／攻速再 +12% |
| 8 | **三线类** | 3 | 2/3 | 三条线伤害 +10%／中线上限 +20% |

> **实装口径**：上两张表里能落到数值引擎的效果（攻击 / 攻速 / 生命 / 分类专精）按原值实现；
> 纯机制效果（穿透、溅射、不占格、复制、反伤、召唤…）折算成等效的 `atk` / `cycle` / `hp` 增量，
> 数值写在 `hex_core.gml` 的 `hex_bond_table()` 里，逐条带注释说明折算理由。
> 大类与小类**相加后一次性成倍**，两者刻意叠加（小类给流派、大类给势力）。
> 档位判定在 `hex_bond_recalc()`，档位一变就 `buff_apply_id++`，让所有卡片立刻重算攻击。

### 2.5 羁绊与"增幅类卡片"的区别（容易混淆，必须写死）
| | 增幅卡（如音盒马、浮生茶） | 羁绊 |
|---|---|---|
| 触发条件 | 需要卡片**放在范围内** | 需要**卡组里带够不同卡** |
| 生效对象 | 范围内指定分类 | 全局任何位置 |
| 数值关系 | 同类取 **max**，不叠加 | 与增幅**乘算** |
| 有代价吗 | 占格子、占卡位 | 占卡组宽度 |

> 实现注意：羁绊与增幅必须乘算但**不可互相读取**，否则会出现"增幅被羁绊二次放大"的循环依赖。

### 2.6 羁绊 UI

- **仅海克斯模式绘制**，其它模式下羁绊栏对象不创建、该区域不绘制（也不留占位）。
- 战斗界面左侧竖排图标，每个图标显示 `当前计数/下一档`，如「直射 4/6」。
- 已达成的档位点亮，未达成显示灰色，hover 显示三档完整效果。
- 放置/铲除时对应图标做一次 0.2 秒缩放反馈，计数器滚动到新值。
- 海克斯选择时，左侧羁绊栏**高亮**本条海克斯会影响的分类，让玩家立刻看出"这条能不能凑成"。

## 3. 海克斯系统

### 3.1 触发规则

> **前置条件**：以下全部只在 `hex_enabled()` 为真时发生。非海克斯模式下不会触发任何一次选择（见 1.1）。

| 触发源 | 时机 | 次数 |
|---|---|---|
| **开局首抽** | 关卡开局布阵阶段，**必出彩** | 每关 1 次 |
| **敌人掉落** | 任意老鼠死亡时 **0.05%** 概率**直接**弹出三选一（暂停全场） | 无上限，但同一时刻只会有一个面板 |
| **单局上限** | 累计 16 条后不再触发新的选择 | — |

> **同一关卡只有一次抽取机会**：`hex_level_repeat()` 判定该关卡是否已经通关过。
> 已经通关过的关卡重玩时，开局不再给抽取，通关也不再入档——与抽卡模式"首通才给奖励"的规则一致。

**落地细则**

- 掉落不再生成地面餐牌。`hex_try_drop()` 命中掉率后**立即** `instance_create_depth(..., obj_hex_panel)`，
  面板 Create 里把 `global.is_paused` 置真，效果就是"掉落 → 暂停 → 三选一"。
- 已经有面板打开时不重复开（`global.hex_pick_open` / `instance_exists(obj_hex_panel)` 双重判定）。
- 非海克斯模式下不执行掉落判定，连 `random()` 都不调用（避免吃掉随机序列，导致其它模式的随机行为出现"开关一次就变"的漂移）。
- 重复挑战的关卡虽然不给抽取，**1.0% 掉落仍然生效**，所以老关卡里仍然可能拿到词条，只是不入档。

**测试关卡豁免（v0.7）**

`test_level`（关卡名「测试关卡」，各岛屿通用入口）**完全不参与海克斯**：

- 不弹首抽面板、不接受掉落、不建 HUD、不刷鼠潮、不写存档；
- 进入时调用 `hex_test_cleanup()`：`hex_reset_run()` 把本局词条与所有倍率清成 1.0，
  并销毁可能残留的 `obj_hex_panel` / `obj_hex_hud`；
- 放置锁不生效（`hex_place_locked()` 首行直接放行），否则整局放不了卡；
- 唯一判定点：`hex_level_excluded()`，复合开关 `hex_active()` = `hex_enabled() && !hex_level_excluded()`。
  会建实例 / 写档 / 弹窗的入口一律用 `hex_active()`，纯数值出口继续用 `hex_enabled()`（此时倍率已是 1.0）。

> 目的：测试关卡是用来量卡片本体伤害的，任何残留的海克斯倍率都会让统计失去意义。

### 3.2 同向双向模型（本版核心约束）

**硬规则：一条海克斯只能有一个方向。** 卡片侧与老鼠侧的效果必须同向——

- **增强型**：卡片变强，老鼠也变强；
- **削弱型**：卡片变弱，老鼠变得更弱。

**「我方增强 + 老鼠削弱」被明确禁止。** 那种组合等于无代价白嫖，会让每一次选择都失去重量，也是本作与金铲铲最本质的差异。

| 形态 | 卡片侧 | 老鼠侧 | 净收益来源 | 占比 |
|---|---|---|---|---|
| **A 加码型** | 增强 | 增强 | 我方增益幅度 **大于** 敌方增益幅度 | 84%（93 条） |
| **C 减码型** | 削弱 | 削弱 | 敌方削弱幅度 **大于** 我方削弱幅度 | 16%（18 条） |
| ~~B 白嫖型~~ | ~~增强~~ | ~~削弱~~ | **禁止** | 0% |
| ~~D 自杀型~~ | ~~削弱~~ | ~~增强~~ | **禁止**（净收益为负） | 0% |

**分档限制（v0.3 已全面放开 C）**

| 稀有度 | 允许形态 | C 条数 | 说明 |
|---|---|---|---|
| 银 | A + C | **5 条** | 银 C 只砍"边缘资源"（攻速 6%、冷却 8%、火苗上限 800），砍完立刻给老鼠一刀更狠的 |
| 金 | A + C | **7 条** | 开始砍主力属性（全队攻击 12%、攻速 12%、经济增速 35%） |
| 彩 | A + C | **6 条** | 砍到伤筋动骨（攻击 25%、攻速 25%、火苗上限对折），换来敌方腰斩 |

> **v0.3 的设计取舍**：v0.2 的"银级全 A"实际上制造了一个舒服区——前期怎么选都不亏，玩家没有紧张感。本版把 C 开到银级，代价是新手前两次选择就可能吃到减码；收益是**从第一秒起就没有"闭眼拿"的选项**。银 C 的幅度被刻意压到最低（我方最多 −6% 攻速 / −15% 生命），新手即使选错也不会崩盘，但必须开始读牌。

**C 型不是"变强"，是"变形"。**

减码型每个选择都在**拿走你的一项能力**，逼你把玩法往另一条路上赶：砍了攻速就得更依赖单发高伤，砍了火苗上限就得更依赖产能卡。压迫感来自"我被迫放弃了一个本来好用的打法"，而不是来自数值被削——这也是它比单纯加强老鼠更有意思的地方。

**这样设计的好处**

1. **选择有重量**：每一条都是交易，不再有"闭眼拿"的选项。
2. **难度自平衡**：越往后越强，老鼠也越强，形成"越强越难"的内生曲线，不会出现后期无脑碾压。
3. **判断成本极低**：面板上两侧同色（都绿 = 加码，都红 = 减码），0.1 秒就能定方向。
4. **压力可见**：压迫指数与鼠潮把"变难"变成屏幕上的数字和怪物，而不是玩家事后才发现的隐性惩罚。

### 3.3 强度点（PP）换算表

为了能客观比较"我方 +10% 攻击"与"敌方 +10% 生命"，统一折算为强度点 PP：

| 效果 | PP |
|---|---:|
| 全队攻击 ±10% | ±1.0 |
| 单一分类攻击 ±10% | ±0.6 |
| 攻击间隔 ±10% | ±1.2 |
| 卡片生命 ±20% | ±0.8 |
| 火苗每波 ±100 | ±0.8 |
| 火苗上限 ±1000 | ±0.5 |
| 冷却 ±10% | ±1.0 |
| 老鼠生命 ±10% | ∓1.0 |
| 老鼠移速 ±10% | ∓1.2 |
| 老鼠数量 ±10% | ∓1.2 |
| 老鼠攻击 ±10% | ∓0.6 |
| 老鼠护甲 ±10% | ∓0.8 |

**净收益公式**

```
净 PP = |卡片侧 PP| − |老鼠侧 PP|
```

- **A 型**：卡片侧 PP 必须 **大于** 老鼠侧 PP（否则等于白送敌人强度）。
- **C 型**：老鼠侧削弱 PP 必须 **大于** 卡片侧削弱 PP。
- 净 PP 为负的词条**不进池**。

| 稀有度 | 净 PP | 说明 |
|---|---:|---|
| 银 | 0.8 ~ 1.5 | 小甜头，代价也小 |
| 金 | 2.0 ~ 3.0 | 能定构筑方向 |
| 彩 | 4.0 ~ 6.0 | 改变这局玩法 |

> 所有词条都按此表估过一遍，表格里的数值是"已经平衡过"的版本。后续新增词条必须过这张表，否则强度会失控。

### 3.4 稀有度与权重

| 稀有度 | 基础权重 | 开局首抽 | 彩的最早出现 |
|---|---:|---|---|
| 银 | 58 | 另两张按权重 | — |
| 金 | 32 | 另两张按权重 | 第 2 次选择起 |
| 彩 | 10 | **其中一张锁定为彩** | 开局即有，此后同左 |

> 开局必出彩是海克斯模式的定调：第一眼就让玩家看到"这条能改变玩法"，而不是先发三张 +6% 攻击。代价是 PI 起步即 3，也就是从第一波起老鼠就 +2.4%。

难度修正：

| 难度 | 银 | 金 | 彩 |
|---|---:|---:|---:|
| 美味级 | 68 | 27 | 5 |
| 火山级 | 63 | 30 | 7 |
| 浮空级 | 58 | 32 | 10 |
| 星际级 | 53 | 33 | 14 |
| 永恒级 | 48 | 34 | 18 |
| 不朽级 | 42 | 35 | 23 |

**C 型出率修正（v0.3 新增）**

稀有度权重决定"多稀有"，C 占比决定"多难受"。两者独立结算三次：

| 难度 | C 占该档池内比例 | 说明 |
|---|---:|---|
| 美味级 | 8% | 银 C 只有 1 条候选，前期几乎不会遇到 |
| 火山级 | 11% | — |
| 浮空级 | 14% | — |
| 星际级 | 17% | 开始能连着吃到两条 C |
| 永恒级 | 20% | — |
| 不朽级 | 24% | 平均每 4 张就有 1 张是减码 |

再叠一层**选择次数修正**：本次选择是第 N 次时，C 占比 `+1.5% × (N−1)`（上限 +9%）。

> 设计意图：同一份运气，在第 1 次选择时是"甜"，在第 10 次选择时是"苦"。这让"拖后期"本身变成一种风险，而不是安全策略。

**保底规则**：连续 2 次选择全部为 C 时，第 3 次强制至少 1 张 A。这是唯一的保护阀——不是为了让玩家舒服，是为了避免极端情况下"三条减码全废"导致构筑直接死亡（那是挫败，不是压迫）。

### 3.5 重随、放弃、上限

| 行为 | 成本 | 限制 |
|---|---|---|
| 重随 | 200 / 400 / 800 火苗 | 每次选择最多 3 次 |
| 放弃 | 获得 120 + 当前波次×40 火苗，**但压迫指数 +2** | 无 |
| 持有上限 | 单局最多 **16 条**（魔塔跨关亦然，`hex_cfg().max_hex`） | 超过后不再触发选择 |
| 互斥 | 见 3.6 | — |

**放弃为什么要付代价（v0.3 改动）**

v0.2 的"放弃 +150 火苗"是一个**安全牌**：牌烂就不选，白拿一笔钱，等于把海克斯系统降级成"抽奖 + 保底"。本版改为：

```
放弃 = 火苗 +(120 + 波次×40) 且 PI +2
```

PI +2 恰好等于拿一条金（见 3.7），意味着**"我不想要这个选择"这个决定本身也要涨价**。想靠"只挑最好的拿、其余全弃"来保持低压，是走不通的——弃得越多，老鼠越强，而且你并没有拿到对等的补偿，只有火苗。

反过来，这让"重随"有了真正的价值：花 200 火苗换一个不涨 PI 的机会，是比弃权更划算的中庸解。

### 3.6 叠加与互斥

1. **数值类可叠加**，但同名词条最多 2 层（表中「叠」列）。
2. **分类专精类**：同一大分类只能有一条专精词条。
3. **机制改写类**：全部互斥，同类机制只保留一条（如「万物皆可炸」与「悬浮厨房」）。
4. **正负同体互斥**：如「大火爆炒」与「面点师」不可共存。
5. **冲突时必须灰显并写明原因**，禁止"拿了才发现冲突"。
6. **减码型（C）单局最多 4 条**：已持有 4 条 C 时，后续选择不再出 C（池内直接过滤）。这一条不是保护玩家，是保护"压迫"的质感——4 条减码已经足够让卡组变形，再多就变成纯粹的残废，玩家只会觉得"这把没了"，而不是"这把很难"。

### 3.7 压迫指数 PI 与「鼠潮」（v0.3 核心新增）

#### 3.7.1 压迫指数怎么算

每一条海克斯都带一个 `pressure` 值，等于它的稀有度档位：

| 来源 | PI |
|---|---:|
| 银 | +1 |
| 金 | +2 |
| 彩 | +3 |
| 放弃（弃权） | +2 |

```
PI = Σ 已持有词条的 pressure + 弃权次数 × 2
```

PI **不会下降**。它是一张只进不出的账单。

#### 3.7.2 数值面（连续）

老鼠**全属性**（生命 / 攻击 / 护甲 / 移速 / 数量）统一乘：

```
老鼠属性倍率 = 1 + PI × 0.008      // 每点 PI = +0.8%
上限 +30%（PI 37.5 触顶）
```

> PI 只在海克斯模式内存在与计算；非海克斯模式下 `global.pi_enemy_mult` 恒为 `1.0`，鼠潮注入函数不调用。

选择时的实际量级：

| 局面 | PI | 老鼠属性 | 直观感受 |
|---|---:|---:|---|
| 2 波小关，拿了 1 银 1 金 | 3 | +2.4% | 几乎无感，只是"有点硬" |
| 常规 5 波关，拿了 4 条 | 8 | +6.4% | 开始需要认真布阵 |
| 9 波关 / 魔塔 10 层，拿了 8 条 | 16 | +12.8% | 明显吃力，容错下降 |
| 魔塔 25 层 + 掉落，拿了 16 条满 | 32~48 | +25.6% ~ **+30%（触顶）** | 每一波都在走钢丝，且必然吃 BOSS 护卫 |

#### 3.7.3 事件面：鼠潮（阶梯）

数值是"暗压"，鼠潮是"明压"——它能被看见、被预告、被针对。

| PI 阈值 | 鼠潮效果 |
|---:|---|
| **10** | 之后每一波额外插入 **1 只精英鼠** |
| **18** | 额外 **2 只** |
| **26** | 额外 **3 只** |
| **32** | BOSS 波追加 **1 只护卫**，且本波所有精英鼠血量 +50% |

- 精英鼠 = 复用关卡数据里已有的精英变体，**不新增美术**，只改生成表。
- 额外精英不算入该波的"击杀数"统计，但**算掉落判定**——压迫本身也带来机会，这是刻意的：越压迫，越可能捡到海克斯餐牌。
- 鼠潮在**波次开始时**结算，插在原有波次队列的尾部，不打断原节奏。

#### 3.7.4 显示规格

- 战斗 HUD 右上角常驻**压力表**：`PI 22 ▮▮▮▯▯　老鼠 +17.6%　下波精英 +2`
- 三选一面板上，每张卡右下角标 `PI +1 / +2 / +3`。
- 悬停时预览：`PI 22 → 23，老鼠 +17.6% → +18.4%`；若将跨阈值，追加一行红字 `下波将出现第 3 只精英鼠`。
- 距离阈值 ≤2 点时，压力表变红并 0.5Hz 闪烁，配一声低频闷响（只在触发时响一次，不循环）。
- PI 超过 26 后，屏幕四周常驻一层极淡的暗红压边（α 0.06），随 PI 上升加深至 0.12——**不遮挡操作，只让玩家"感觉被围住"**。

#### 3.7.5 为什么用 PI，而不是直接"每关 +X%"

| 做法 | 问题 |
|---|---|
| 每关固定加难 | 与本局选择无关，玩家觉得"策划在整我"，且高手与新手感受相同 |
| 只靠 A 型词条自带的敌方加成 | 数值散落在 90 多条词条里，玩家算不清自己到底多难，挫败时找不到原因 |
| **PI 集中记账** | 一个数字解释全部压力，玩家能精确归因到"我拿了 16 条"；也能主动权衡"这条要不要拿" |

PI 的真正作用是**把难度从隐藏变量变成公开变量**。玩家的决策从"哪条更强"变成"哪条更强、且这份强我承担得起"。

#### 3.7.6 PI 的重置规则

| 场景 | PI |
|---|---|
| 普通岛屿关 | 每关开始时清零（关卡之间独立） |
| 魔塔 / 龙渊 / 浮空 / 海底连续序列 | **跨关累积不清零**，整条序列算一局 |
| 海克斯模式（任意难度） | 同上，无额外处理——它已经不再是"某个模式的特例"，而是系统的唯一存在环境 |

> 这条规则让"魔塔"成为真正的 roguelike 一局：35 层爬完，PI 会一路从 3 涨到 30 左右，最后几层必然在精英鼠堆里硬打高难 BOSS。这是本作最接近"金铲铲后期团战"的体验。

### 4.4 词条写作规范

**必须有**：稀有度、卡片侧、老鼠侧、形态（A/C）、叠层、互斥、实现锚点。

**硬性配平规则**

| 形态 | 约束 |
|---|---|
| A | 卡片侧 PP **>** 老鼠侧 PP，净 PP 落在该档区间 |
| C | 老鼠侧降幅 PP **>** 卡片侧降幅 PP，且倍数 **≥1.3 倍**（压迫版要求：让出的必须换回明显更多） |
| 任意 | 净 PP 为负 → 不进池 |

> C 型的 1.3 倍是 v0.3 新加的硬线。v0.2 只要求"敌方降更多"，导致部分 C 词条（如攻击 −15% / 移速 −35%）虽然合格，但玩家体感是"没赚"，下次干脆不选。1.3 倍保证每一张 C 都是"肉疼但真香"。

**禁止**：
- **卡片侧增强同时老鼠侧削弱（B 型白嫖），这是硬性红线**；
- 只写一方；
- 两侧方向不一致（一增一减）；
- 净 PP 为负；
- 用"大幅""显著"代替数值；
- 一条同时改三个以上系统；
- 依赖难以感知的隐藏判定。

**自查句式**：把词条读两遍——"我方 XX，同时老鼠也 XX（同一个字：变强 / 变弱）"。读不通就说明方向写反了。

### 4.5 原表描述 → 实际实现（6 条改写对照）

> 「描述即实现」不等于「照抄需求」。以下 6 条的原表机制在本作引擎里**没有落点**（要么没有复活系统，要么星级由卡面存档每帧重建，要么对局内不能改卡组），
> 如果硬留着原文案就是"写着一套、跑着另一套"。处理原则：**改成等效强度、且真正会触发的效果，文案同步改写**。

### 5.1 流程

1. 触发（波次/拾取餐牌）→ `global.is_paused = true`，全场敌人、子弹、计时、动画全部冻结。
2. 背景压暗（`draw_set_alpha` 0→0.55，200ms 缓动），镜头不做位移。
3. 三张卡在屏幕中央横排，间距 40px，整组尺寸约占屏宽 60%。
4. 入场：每张卡 `scaleX` 0→1 翻牌，间隔 100ms 依次出现（左→中→右）。
5. 玩家选择 → 被选卡片放大 1.15 倍 + 光爆 → 词条文字飞向左侧栏 → 其余两张淡出。
6. `global.is_paused = false`，恢复对局。

### 5.3 面板必须显示

- 顶部：「第 N 次选择」+ 当前已持有海克斯数量 + **压迫指数**（`PI 22　老鼠 +17.6%`）。
- 每张卡：稀有度、形态标记（**加码 ▲ / 减码 ▼**）、词条名、两段效果（卡片侧在上、老鼠侧在下）。
- **配色规则**：两侧**同向同色**——加码型两行都是绿色（我方增益在上、敌方增益在下，都用绿），减码型两行都是红色。玩家扫一眼颜色就知道这条是"再强一点还是再难一点"，不需要逐字读。
- 形态标记同时决定卡框内侧一道 4px 的竖色条：加码=绿，减码=红，与稀有度边框并存不冲突。
- **PI 标签**：每张卡右下角标 `PI +1 / +2 / +3`；悬停时显示 `PI 22 → 23　老鼠 +17.6% → +18.4%`。
- **跨阈值预警**：若选择后 PI 会跨过 10/18/26/32 任一阈值，该卡下方追加一行红字 `下波将出现第 N 只精英鼠`，并配一次低频闷响。这是压迫感的"预告"，比事后被打一顿更有效。
- 冲突提示：与已持有词条互斥时整卡灰显，并显示"与「XX」冲突"。
- 底部：「重随（200/400/800）」按钮 + 「放弃（+120，PI +2）」按钮 + 剩余重随次数。
- 左侧：羁绊栏高亮本条涉及的分类，并显示"选择后 X 类将达到 Y 档"的预演文字。
- **减码卡额外提示**：整卡底部加一条 12px 的暗红细条，文字 `本条会削弱你的一项能力`——银 C 尤其需要，因为新手第一次遇到会以为看错了。

**实现要点（踩坑预警）**

```gml
// ❌ 错误：在 Step 里直接改 scroll_y
// 某些鼠标滚轮一次点击会连续触发 2 帧事件，表现为"滚一格跳两格"
scroll_y -= mouse_wheel_up() * 72;

// ✅ 正确：事件里只累加目标值，Step 里做缓动
// Mouse Wheel Up 事件
scroll_target = max(0, scroll_target - 216);
// Step
scroll_y += (scroll_target - scroll_y) * 0.35;
scroll_y = clamp(scroll_y, 0, max(0, list_height - view_h));
```

- `scroll_target` 是权威值，`scroll_y` 只是表现值，**渲染与点击判定一律用 `scroll_target`**，否则会出现"看到的是第 4 项、点到的是第 5 项"。
- 列表用 `draw_rectangle` + 动态文字绘制，**不要**为 111 个条目各建实例（内存与排序开销都不值得），只绘制视口内 6~8 项。
- 筛选切换时 `scroll_target` 归零并清空惯性。

- 页头一行提示：`本局词条为临时，通关后才会记入「已解锁」`。

function pi_recalc() {
    if (!hex_enabled()) {                 // 非海克斯模式：恒等值，绝不留 undefined
        global.hex_state.pi  = 0;
        global.pi_enemy_mult = 1.0;
        global.pi_elite_extra = 0;
        global.pi_boss_escort = false;
        return;
    }
    var _p = global.hex_state.giveups * 2;
    for (var i = 0; i < array_length(global.hex_state.picked); i++) {
        _p += hex_pressure(global.hex_state.picked[i].tier);

    global.hex_state.pi = _p;
    global.pi_enemy_mult = min(1 + _p * hex_cfg().pi_rate, 1.30);   // 老鼠全属性，硬上限 +30%

    global.pi_boss_escort = (_p >= 32);
}

**BOSS 的两条额外约束**（v0.9）：

1. **必须单独挂**。BOSS 在 `obj_battle/Step_2.gml` 里自己 `instance_create_depth`，不经过普通鼠的组波循环，漏一处就是"BOSS 完全不压迫"。
2. **不吃移速**。BOSS 的位移由状态机按坐标硬推（遁地、瞬移、跳跃、绕场），`move_speed` 一改就和技能落点错位，表现为"瞬移抖动"。用 `hex_enemy_scale_boss(inst)` 走 BOSS 口径。

### 6.1 持久化：只有通关才入档（v0.4 核心）

**三条铁律**

1. 本局词条**只存在内存**（`global.hex_state.picked`），绝不逐次落盘；
2. 唯一的落盘点 = **胜利瞬间的 `hex_on_win()`**（v0.6 起；`complete_level()` 只作兜底）；退出、失败、关游戏都不写；
3. 写入是**累计获得次数**，不是覆盖存档，也不是"解锁后才可用"。

为什么挂 `complete_level` 而不是自己找胜利判定：它是工程里唯一"通关即存档"的既有出口（`array_push(completed_levels)` + `save_file` 一次完成），魔塔、龙渊、活动关全都复用同一入口，不需要按关卡类型分支。少一个写入点，就少一处"通关了但没记上"。

**改法（注意原函数的提前 return）**

`scripts/edit_file/edit_file.gml:145` 的现状是"该关已通关就直接 `return true`，不保存"：

```gml
function complete_level(level_id) {
    for (var i = 0; i < array_length(global.save_data.completed_levels); i++) {
        if (global.save_data.completed_levels[i] == level_id) {
            return true;          // ← 提前返回，后面的记账代码根本不会执行
        }
    }
    array_push(global.save_data.completed_levels, level_id);
    save_file(global.save_slot);
    return true;
}
```

所以记账必须放在循环**之前**，否则"重复通关"永远累计不到次数：

```gml
function complete_level(level_id) {
    var _is_new = (array_get_index(global.save_data.completed_levels, level_id) == -1);

    hex_commit_run(level_id);          // ① 先记账（重复通关也累计）

    if (_is_new) {
        array_push(global.save_data.completed_levels, level_id);
    }
    save_file(global.save_slot);       // ② 统一保存，避免两条路径漏存
    return true;
}
```

```gml
/// @function hex_commit_run(level_id)
/// @desc 把本局词条写进存档；非通关状态或序列未到末关时什么都不做
function hex_commit_run(_level_id) {
    if (!hex_enabled()) return false;                 // 非海克斯模式：一条都不写
    if (!hex_run_is_cleared()) return false;          // 兜底：非通关不写
    if (!hex_run_scope_end(_level_id)) return false;  // 魔塔等序列未到末关也不写

    if (array_length(global.hex_state.picked) == 0) return false;   // 空手通关不写

    // 旧存档兼容，写法与 completed_elite_levels 一致
    if (!variable_struct_exists(global.save_data, "hex_unlocked")) {
        global.save_data.hex_unlocked = [];
    }
    if (!variable_struct_exists(global.save_data, "hex_stats")) {
        global.save_data.hex_stats = { runs_cleared: 0, runs_abandoned: 0, best_pi: 0 };
    }

    var _today = date_string_of(date_current_datetime());
    var _list  = global.save_data.hex_unlocked;

    for (var i = 0; i < array_length(global.hex_state.picked); i++) {
        var _id  = global.hex_state.picked[i].id;
        var _hit = -1;
        for (var j = 0; j < array_length(_list); j++) {
            if (_list[j].id == _id) { _hit = j; break; }
        }
        if (_hit == -1) {
            array_push(_list, { id: _id, count: 1, first_date: _today, last_date: _today });
        } else {
            _list[_hit].count += 1;
            _list[_hit].last_date = _today;
        }
    }

    global.save_data.hex_stats.runs_cleared += 1;
    global.save_data.hex_stats.best_pi =
        max(global.save_data.hex_stats.best_pi, global.hex_state.pi);

    return true;    // 真正的 save_file 由调用方统一做
}
```

> **v0.6 修正（实机踩到的两个真 bug，必须按这个来）**

> **① 挂载点从 `complete_level()` 挪到「胜利瞬间」`hex_on_win()`。**

> 现在的做法是挂到胜利判定本身（`obj_travel_record` / `obj_beverage_machine` /

> 由 `hex_on_win()` 内部再调 `hex_commit_run()` 并自己 `save_file`。

>
> **② 不要先 `var _list = global.save_data.hex_unlocked;` 再 `array_push`。**

> 但它同样是一次"通关离场"，`obj_battle/CleanUp_0` 不能因此把本局清空，否则续关会丢构筑。

### 6.1.1 已解锁 = 永久生效（v0.8）

v0.7 及以前，`hex_unlocked` 只是一份"图鉴"：通关记了次数，但词条效果在下一局就没了。
v0.8 起它同时是**永久加成池**，本局通关后，这些词条在之后的对局里继续生效。

| 项 | 规则 |
|---|---|
| 生效范围 | 仍是海克斯模式专属；测试关卡不参与（`hex_active()` 为假） |
| 生效层数 | 每条按 `min(取得次数, 词条自带 stack 上限)` 叠层，与单局叠层规则一致 |
| 名额 | **不占本局 16 条上限**，也不参与本局记账；`hex_state.persist` 单独存放 |
| 压迫 PI | 永久层也计入 PI（反正单局 16 条就足以把 PI 顶到 32，影响有限） |
| 建局时机 | `hex_state_init()` 末尾调 `hex_load_collection()`，每局重建一次，幂等 |

**实现要点**

```gml
function hex_load_collection() {
    if (!hex_active()) return 0;                 // 测试关卡 / 非海克斯模式：不并入
    global.hex_state.persist = [];               // 重建，避免重复并入
    for (每条 global.save_data.hex_unlocked) {
        var _stack = min(entry.count, def.stack);
        for (var k = 0; k < _stack; k++) hex_apply_core(entry.id);   // 只算数值
        array_push(global.hex_state.persist, { id, stack: _stack, tier, form });
    }
    hex_pi_recalc();
}
```

`hex_apply()` 被拆成 `hex_apply_core()`（纯数值）+ 记账薄；单局抽取走 `hex_apply()`，
永久收藏走 `hex_load_collection()`，两者共用同一份数值合并代码，不会出现"局内生效、永久不生效"的分叉。

**两道防爆夹逼（必须保留）**

1. 卡片侧沿用 `hex_sync_globals()` 的夹逼：`atk ≤ 8.0`、`cycle ≥ 0.30`、`hp ≤ 5.0`；
2. 老鼠侧新增夹逼（`hex_enemy_mult`）：`hp 0.30~4.0`、`atk 0.30~3.0`、`spd 0.40~2.5`。
   之前老鼠侧没有任何上限，收藏一多会叠到几十倍，卡片侧 8 倍攻击根本追不上。

**火苗上限要用差值同步**：`hex_sync_flame_cap()` 记 `global.hex_flame_cap_applied`，
只把「当前 `_s.flame_cap` − 上次已应用值」加到 `flame_cap_base`。
永久词条每局都会重新并入，直接累加会让上限每进一关涨一次。

### 6.2 「一局」的边界（决定退出惩罚有多重）

| 序列类型 | 一局 = | 落盘点 |
|---|---|---|
| 岛屿正关 / 困难关 | **单关** | 该关结算 |
| 魔塔 / 龙渊 / 浮空 / 海底 | **整条序列** | 序列最后一关 |

> 以上三种都只在海克斯模式下产生落盘行为；其它模式通关时 `hex_commit_run()` 首行即返回，存档中 `hex_unlocked` 不会有任何增量。

理由：PI 在魔塔里是**跨关累积**的（3.7.6），如果每层都把词条写档，玩家爬到 30 层失败也能白拿十来条词条，"退出即重抽"就形同虚设。**一局的边界必须和 PI 的生命周期一致。**

`hex_run_scope_end(level_id)` 的实现建议：不改关卡 JSON，直接读 `scripts/maps_init/maps_init.gml` 里该序列的关卡数组，判断 `level_id` 是否为末位。以后加关卡不用同步维护。

### 6.3 模式隔离在存档层的体现

| 问题 | 结论 |
|---|---|
| 海克斯模式通关的词条，会不会让经典模式变强？ | **不会。** 双重保险：`hex_unlocked` 不参与任何数值计算（见 7 护栏），且非海克斯模式下 `hex_mult` 恒 1.0。 |
| 经典模式能不能看到已解锁词条？ | **不能。** 入口按钮不创建（5.5.1），暂停面板也没有「词条」页签。 |
| 经典模式通关会不会写 `hex_unlocked`？ | **不会。** `hex_commit_run()` 首行判 `hex_enabled()`。 |
| 切换模式后本局数据怎么办？ | `hex_run_reset()` 全清，不存在超限灰显（1.2.2）。 |
| 玩家一直只玩经典模式，存档里 `hex_unlocked` 会是什么？ | 空数组 `[]`，`hex_stats` 全 0。列表页打开即空状态，不会报错。 |

**实现上的一条硬要求**：`hex_unlocked` 的读写都必须经过 `hex_enabled()`，**不要**因为"读一下又不会怎样"就放开。曾经的坑是：早期版本为了让经典模式也能看收集度，把读取放开了，结果列表页在非海克斯模式下仍会创建对象并逐帧绘制——玩家看不到，但每帧都在算，还顺手改写了 `global.hex_state`，导致切回海克斯模式时 PI 是脏的。

## 7. 平衡护栏

| 维度 | 上限 | 理由 |
|---|---|---|
| 单卡攻击倍率 | ×8（增幅 + 羁绊 + 海克斯合计） | 超过后一枪秒 BOSS |
| 攻击间隔 | 不低于原值 30% | 防止子弹数量爆炸 |
| 攻击范围 | +2 行 / +50% 半径 | 防止全屏覆盖 |
| 火苗上限 | 通常 ≤ 9999（「无限续杯」例外） | 防止经济词条互叠后不用思考 |
| 单局海克斯 | **16 条**（`hex_cfg().max_hex`） | 保证词条池 ≥ 111 条时不会抽干 |
| 羁绊档位 | 每分类最多 3 档 | 防止计数溢出导致数值失控 |
| **压迫指数倍率** | 老鼠全属性 **≤ +30%**（PI 37.5 触顶） | 超过后精英鼠血量会盖过 BOSS，关卡失去层次 |
| **鼠潮数量** | 每波额外 **≤ 3 只**精英 | 再多会拖长波次时长，节奏崩坏 |
| **C 型累计** | 单局最多 **4 条** | 防止"四条减码"把卡组砍成残废，那是挫败不是压迫 |
| **已解锁词条** | **不提供任何数值加成**，且只在海克斯模式可见 | 否则老玩家无限滚雪球，新玩家永远追不上；藏品就只是藏品 |
| **模式参数** | 必须经 `hex_cfg()` 读取；是否启用必须经 `hex_enabled()` 判定 | 散写 `play_mode == 4` 必然外溢；只判参数不判开关会漏掉 HUD/存档/UI（见 1.2.1） |

**高危组合（需重点测试）**：
- 「现炒现卖」+「逆火」+「快手翻炒」+ 直射羁绊 3 档 → 攻速可突破上限
- 「无限续杯」+「剩菜打包」+「老汤续杯」→ 火苗通胀
- 「满席羁绊」+「编外厨师」+「一菜三吃」→ 一次凑满多条 3 档
- 「破釜沉舟」+ 0 费卡 → 永久满火苗（需限制费用下限）
- **「断火」+「空锅」+「冰封千里」同时持有 → 攻击 −25%、攻速 −25%、冷却 +40%，DPS 掉到 30% 以下**，此时若 PI 已过 26（3 只精英），几乎必死（需实测确认「C 型累计 4 条」上限是否够）
- **「少油」+「慢工出细活」+「冰窖」叠加后攻击间隔接近 +40%**，配合直射羁绊 3 档的 −14% 会互相抵消，玩家会困惑"为什么没生效"（需在 UI 上显示攻击间隔总和）
- **弃权流**：连续 5 次弃权 → PI 10 但零收益，直接进鼠潮（这是刻意的惩罚，但需要确认不会出现在第一关就必死的情况）
- **跨模式残留**：从海克斯模式退出后直接进经典模式，`global.hex_state` 若未清空，`pi_recalc()` 会在经典模式里把 PI 重新算出来。必须在关卡初始化时无条件调一次 `hex_run_reset()`，不能只在"切换模式"时调

### 8.2 关于「纯机制类词条」的折算（重要）

111 条里有 77 条的效果是引擎里不存在的机制（穿透、溅射、复制、召唤、地形改写、不占格……）。
本作没有这些开关，逐条改造会伤到本体玩法，所以这 77 条统一按**等效战力折算**进现有数值通道：

```
atk / cycle / hp          全队通用增量
cat_atk / cat_cycle       [[分类名, 增量], ...]，大分类或小分类
flame_start / flame_wave / flame_cap / flame_growth / wave_flame_pct
flame_tick (+flame_tick_sec) / heal_wave / free_reroll
```

- 数值部分（攻击 +X%、生命 +X%、火苗 +N、分类 +X%）**保持文档原值**，不做折算。
- 机制部分按同档位的等效战力折算，注册表里标 `approx: true`，面板和列表显示「≈ 等效折算」，描述文本仍是设计原意。
- 折算结果：111 条全部可抽取，池子分布 银 A38/C5、金 A32/C7、彩 A23/C6 —— 首抽必彩有 23 张可选，不会每局都撞同一张。

5. **银/金/彩的六档难度权重**是否需要按当前版本的实际通关率再调？
6. **羁绊栏放在左侧还是顶部**？左侧竖排符合自走棋习惯，但本作左侧可能是卡片栏，需要确认 UI 空间。
7. ~~减码型（C）只留 7 条够不够~~ → **已定：扩到 18 条，银级也开 C**（v0.3 压迫版）。剩余待定项见下。

**v0.3 新增待确认（都与"压迫强度"直接相关）**

8. **PI 的斜率 0.8%/点 是否太陡**？叠上 A 型词条自带的敌方加成后，后期可能是"双倍难度"。16 条满配 ≈ +25.6%（混搭）~ +30%（全彩触顶）。建议先按 0.6% 跑，实测后再定。
9. **弃权 PI +2 会不会让"烂牌局"直接暴毙**？如果第 1 关连吃 3 次烂牌，PI 6 但零收益，等于开局欠债。备选方案：第 1 关弃权不计 PI，或弃权 PI 改为 +1。
10. **鼠潮额外精英要不要计入"本波敌人总数"**？目前写的是不计击杀、算掉落。如果计总数，会连带影响"本波零死亡"类词条（如一锅端）的判定。
11. **要不要做"高压奖励"**？例如 PI ≥ 26 时掉落率从 1.0% 提到 2.0%，形成"越难越有翻盘机会"的正反馈。这条会显著改变体感，属于可选加项。
12. **压力表放右上角是否与现有 HUD 冲突**？需要确认右上角是否已被火苗/波次占用。

**v0.4 新增待确认（全局 / 隔离 / 持久化）**

13. ~~「已有词条」按钮是否限定海克斯模式可见~~ → **已定：仅海克斯模式可见**（v0.5）。
14. **「已有词条」只是藏品，还是反过来影响抽池**？当前定为纯藏品（7 护栏：不提供任何数值加成）。另一种做法是"只有解锁过的词条才会被抽到"，但那会让新玩家第一局无牌可抽，需要额外保底池，工作量翻倍。
15. **魔塔/龙渊"一局"的边界**：整条序列（当前写法，退出全丢）还是单层（更宽松，但能靠反复退出刷词条）？这是"退出即重抽"惩罚力度的开关。
16. **失败也要清空吗**？当前写的是清空。若觉得太狠，可在失败结算给"保留 1 条"的仁慈选项。
17. **词条被删/改名后，旧存档里的记录怎么处理**？建议保留并标 `orphan`，UI 显示「已移除词条」，否则收集度会莫名下降。
18. **海克斯模式要不要单独一套难度权重**？当前银金彩权重沿用同一张表（3.4），因为系统已不再与其它模式并存，无需再做"模式间差异权重"。

**v0.5 新增待确认（都关于"独占"的边界）**

19. **旧四个模式该不该在设置页给出提示**？关闭海克斯模式时，设置页是否要显示一行灰字「海克斯玩法仅在海克斯模式开放」？不加的话，玩过海克斯模式的玩家在经典模式里找不到羁绊栏，可能会以为 bug。
20. **海克斯模式是否强制要求已通关**？之前定位是"给老玩家"，但技术上没限制。建议放开（玩家自己选难度），只在开关旁标一行「高压玩法，建议先通关一遍」。
21. **`hex_unlocked` 在非海克斯模式要不要彻底不加载**？当前做法是"数据留在存档里，但不读不写不显示"。另一种做法是切模式时把整个字段剥离到独立槽位，更干净但迁移成本高。建议保持现状。
22. **教学关是否也允许海克斯**？当前归为不生效例外（1.1.1）。如果海克斯模式的新手教程要做，这条要翻过来。

### B.3 已知设计取舍

1. **认知偏差**每次并入只触发一次：局内抽到立刻改判，永久解锁则每关开局触发一次。
2. **均值**取 `obj_card_slot.cost`（基础费用）而非当帧 `current_cost`，避免同帧内各卡槽 Step 执行顺序导致的抖动。
3. **出怪间隔**缩放后有 1 帧下限，否则倍率叠低会把 `wave_timer` 取整成 0、同一帧刷满全场。
4. **周期效果在暂停时不推进**，但「认知偏差」的改判放在暂停保护之前，否则在面板里确认选卡后不会生效。
