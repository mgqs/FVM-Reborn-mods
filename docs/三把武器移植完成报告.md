## 九、工具脚本（`tools/`）
| 脚本 | 用途 |
|---|---|
| `import_weapon_sprites.ps1` | 导入三把武器全部精灵（`-Weapon` / `-DryRun`） |
| `build_weapon_objects.ps1` | 生成 15 个对象（.yy + 事件 gml，自动做 GML 适配） |

> 所有 .ps1 必须存为 **UTF-8 with BOM**，否则 Windows PowerShell 5.1 按 ANSI 读取，中文注释里的字节会被误认成引号/括号，导致 ParserError。

## 十、编译前注意
1. 打开 GMS2 IDE 时若提示资源重新加载，选「是」；精灵与对象都是外部手写，IDE 首次打开会重建索引。
2. 若出现 `obj_death_scythe_gem_*` 红叉，检查该对象 `.yy` 的 `spriteId` 是否指向已导入的 `spr_death_scythe_gem_N`。
3. `death_scythe` 的宝石对象用 0.9 缩放（88×88 素材直接当图标，源没有 45×45 的 gem_effect），若视觉偏大/偏小只改 `Create_0.gml` 的 `image_xscale/yscale`。
4. `super_weapon` 槽位上 `hades_scythe` 与 `death_scythe` 互斥（同槽位只能装一把），换装时 `weapon_gems_reconcile` 会自动卸下不兼容的专属宝石，宝石本身不丢失。
