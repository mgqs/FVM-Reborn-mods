# 字体与字形维护

> 项目：《美食大战老鼠：重生》　最后更新：2026-10-27（字形库补全）

## 1. 为什么会出现"方框"

GameMaker 的字体资源是**按字形表打包**的，不是全字库：

```
fonts/<name>/<name>.yy     ← glyphs: 每个字符在图集里的坐标 (x,y,w,h) 与度量 (offset / shift)
fonts/<name>/<name>.png    ← 字形图集（白字 + alpha）
```

`glyphs` 里没有的字符，运行时直接画 `.notdef`（空心方框）。IDE 只有在**打开字体编辑器并保存**时才重新栅格化，
所以"只缺几十个字"的场景不能靠改 `.yy` 的 `ranges` 解决——必须把字形真正画进 png。

## 2. 字体清单

| 资源 | 原字体（fontName） | 尺寸 | 行高 | 主要用途 |
|---|---|---|---|---|
| `font_yuan` | 獅尾麥克黑體SC-Black | 16pt / em≈21px | 28 | UI 主字体（160 处 `draw_set_font`） |
| `font_hei` | HarmonyOS Sans SC | 18pt / em≈24px | 27 | 说明文、Scribble 默认字体（51 处） |
| `font_pixel` | Unifont | 12pt / em=16px，无抗锯齿 | 17 | 像素风小字（40 处） |
| `font_number` | Redressed | 15pt | 24 | 纯数字 |
| `font_song` | 阿里妈妈方圆体 VF Thin | 16pt | 28 | 卡槽快捷键提示（仅 ASCII） |
| `font_song2` | 华文宋体 | 18pt | 33 | 无直接绘制（仅 Scribble 字形合并用） |

> 原字体文件（獅尾麥克 / HarmonyOS Sans / Unifont / 华文宋体）都不在本机，本仓库只保存栅格化结果。

## 3. 补字工具

```bash
python tools/font_fill.py --dry-run     # 预览要补哪些字、占几行图集（不写盘）
python tools/font_fill.py               # 真正写入（自动备份到 fonts/<name>/*.bak_<时间>）
python tools/font_fill.py --font font_hei
python tools/font_fill.py --only-screen # 只补项目文案里真正缺的字
```

工具做的事：

1. **取源字形**：本机没有原字体，改用系统的 `NotoSansSC-VF`（思源黑体），
   按「墨密度 + 字面框高度」自动校准字号与字重，使新字形和原字形同粗细同大小
   （实测 `font_yuan` wght≈500、`font_hei` wght≈320、`font_pixel` 16px 二值化）。
2. **对齐基线**：用已有汉字反推「渲染底边」该落在窗口的哪一行，统一偏移，避免补进去的字整体偏上/偏下。
3. **排进图集**：沿用原排布（行首 x=6、字间距 3、行高 = 字形高 + 2），右侧与底部留 3px
   （纹理组 `border:2`，贴边会溢出）。
4. **校验**：越界 / 新旧重叠 / 字段完整性 / `ranges` 与 `glyphs` 一致，任一不过就中止。
5. **预览**：把新字形与老字形混排成一句话，输出到 `.workbuddy/tmp/`，用眼睛确认对齐。

字符集优先级：**项目上屏缺字 → GB2312 符号区 → GB2312 一级汉字 → GB2312 二级汉字**，
图集放不下时后面的自动截断（二级生僻字会让位）。

## 5. 注意事项

- **不要在 IDE 里打开这三个字体资源再点确定**。本机没有原字体，IDE 会尝试重新栅格化并替换字体，
  已有的补字成果会被冲掉。要改字形请跑 `tools/font_fill.py`。
- 补完字体后 **Build → Clean（Ctrl+F7）再 F5**，否则可能命中旧的 texture 缓存。
- 以后新增文案若出现方框：直接跑 `python tools/font_fill.py --only-screen`，
  它只补当前缺的字；若提示"空间不足"，说明该字体图集已满，需要考虑换字体资源或扩图集（有纹理页上限风险）。
- `obj_menu_manager/Create_0.gml` 里有一段 `scribble_super_glyph_copy_all` 的运行时合并
  （font_yuan / font_pixel → font_hei / font_song / font_song2），**只对 Scribble 绘制的文本生效**，
  原生 `draw_text` 不吃这一套。字体本身补全后这段仍可保留（互为兜底）。
- **补字会连带撑爆 Scribble 的描边烘焙页**。`obj_menu_manager` 启动时会调
  `scribble_font_bake_outline_4dir("font_hei", ...)`，把字体**全部字形**（含 4 向描边的 4px 外扩）
  排进一张正方形页；补字前 3416 字形在 2048×2048 刚好够，补到 **5970 字形后就不够了**，
  原来会直接 `show_error(...)` 终止游戏（报 `No space left on 2048x2048 texture page`）。
  现已改为由 `__scribble_bake_autosize()` 复刻排布算法、按 256 步长找「刚好装得下」的边长
  （当前算出 **2304**，约 21MB），装不下才回落到原来的报错。**以后继续补字不用再手改数字**，
  但字形数若继续上涨、边长涨到 4096 以上，显存占用会明显增加，届时应考虑拆分字库或减少烘焙字形。
