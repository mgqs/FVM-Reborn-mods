# 二期海克斯可行性评估

> 评估对象：`桌面/二期海克斯.md` 里的 **68 条**新词条（编号 184~259）
> 评估基准：当前工程 `FVM_Reborn-mod`（海克斯已上线 111 条 + 二批 hex_112~184）
> 结论：**可实现 66 条**（其中 47 条可直接落地、19 条需补一小层机制），**不可实现 2 条**

---

## 0. 一句话结论

这批词条里绝大多数只是"给现有数值通道加个条件"，工程里已经有现成的挂钩点；真正麻烦的是三类：

1. **需要"伤害归属"的**（哪张卡打的）——子弹目前不记来源，好在 122 个子弹都继承 `obj_bullet_parent`，可以在父对象 Create 里统一捕获；
2. **需要"标签/组"的**（五指、残响乐团、词条互斥）——当前 registry 没有 `group` 字段，加一个即可；
3. **纯资源缺失的**（全屏视频）和**要重写子弹模型的**（帧伤）。

## 4. B 组：需要补一小层机制（19 条）

> 都能做，但要先把"缺的那一层"补上。工作量：S ≈ 半天、M ≈ 1~2 天、L ≈ 需要动多个系统。

### 4.1 病毒系列（187 / 188 / 189）— 工作量 M

缺：常规鼠 → 感染鼠的映射与生成期替换。
现成条件很好：感染系敌人统一命名为 `infected_` + 原 id（`infected_normal_mouse`…`infected_zhanshen`，共 19 只，含 6 个 BOSS）。

做法：
- 增伤侧：`hex_damage_taken_mult()` 里 `string_pos("infected_", mouse_id) > 0` 即生效；
- 替换侧：在 `obj_battle/Create_0` 组波循环（`hex_enemy_scale()` 旁边）加 `hex_infected_swap()`，查注册表里有没有 `"infected_" + id`，有则按概率替换 `_obj / mouse_id / spr`；BOSS 走 `obj_battle/Step_2` 的 BOSS 生成口同样处理。
- 三档递进（5% / 20% / 100%）天然满足"有对应跨服鼠军时"才替换——没有感染版的鼠保持原样。

### 4.2 五指组 / 残响乐团（195 / 231）— M

缺：词条"组"标记与组倍率层。
做法：registry 加 `group: "五指"` / `"残响"`；`hex_apply_core` 里对组内词条的**增量**统一乘组倍率（`_s.x * (1 + delta * mult)`），不是把最终值翻倍——否则会给到重复加成。

231 额外要求"移除不公契约的负面"，做法是加 `hex_state.contract_penalty_off = true`，五个契约的负面分支统一判这个开关。

### 4.3 类别打乱（197）— S

做法：开局 `card_category_init()` 之后，把"攻击类"卡（有 atk 且不是产能/防御/增幅）的 `major` 在 直射/追踪/投掷/喷壶/多向/防空 之间随机重排，写回 `global.card_category_map`。
羁绊面板读的就是这份 map，会自动跟着变——效果说明里要写清"羁绊也会跟着乱"。

### 4.4 Hana 的四卦（207）— M

缺：4 选 1 面板 + 一次性 buff 容器。
做法：复用 `obj_hex_panel`，把 `hex_panel_card_rect` 改成"按 offer 数量居中"（现在是固定 3 张左对齐，加第 4 张会溢出右边）；开局强制 offer = 4 条内部伪词条，选完写 `hex_state.hana_pick`，buff 落到 atk / hp / 火苗 / 首三张免费 四个通道。
老鼠侧"随机一个生效"不需要面板，开局 roll 即可。

### 4.5 您的盾牌（209）— S

缺：固定减伤通道；卡片"防碾压"没有落点（**卡片本身不会被碾压**，碾压只作用于老鼠）。
做法：`Other_10` 里 `damage_amount = max(1, damage_amount - flat_dr)`；卡片侧在 `hex_card_incoming_damage` 里减 25。
建议把"防碾压"改成「免疫灰烬秒杀」，否则这条对卡片是空描述。

### 4.6 决斗（211）— M/L

缺：单目标锁定 + 伤害归属。
做法：每张攻击卡维护 `hex_duel_target`；非目标伤害 ×0.2（"仅攻击一个目标"只能近似，因为子弹是自由飞行）；"对同一目标递增至 25%"用目标 id + 连击数。
严格实现需要"子弹只对锁定目标结算"，这就要动子弹命中判定，成本会涨到 L。

### 4.7 情报收集（213）— S/M

缺：情报岛"已查看"记录（现在只展示、不记录）。
做法：`save_data.info_seen` 数组，`obj_info_island_bg` 绘制敌人详情时写入；战斗里按 `mouse_id` 查表 +20% / -20%。
**注意**：老存档没有记录，一进关会全是 -20%，需要一次性把已有存档标记为"全部已读"。

### 4.8 血魔的渴血（228）— M

缺：伤害归属（哪张卡打的）。
可行路径：`obj_bullet_parent/Create_0` 里捕获创建者（`other`），存 `hex_src`；`Other_10` 结算后按 `hex_src` 回血。
上限增长要接进"纯上限"公式（`base_max_hp × 词条 × (1+层数)`），否则会和「取长补短 / 山脉龙魂」互相抹（v0.13 踩过）。
300% 上限极强，建议 150%。

### 4.9 不公的契约（229）— L

五个契约逐个看，机制都在，但要分别落地：

| 契约 | 落点 | 难度 |
|---|---|---|
| 光明：火苗价值 +50，溢出时产火卡受伤 | `obj_flame` 的 `value`；溢出判定 `global.flame >= global.flame_cap` | S |
| 力量：攻击 +100%，非攻击状态每秒 -1% 上限 | `CARD_STATE` 判定 + 定时伤害 | S |
| 自由：每 30 秒随机改卡耗能 | 已有 `hex_batch2_cost` 那套出口 | M |
| 神速：攻速 +100%，非攻击状态每秒 -1% 上限 | 同力量 | S |
| 增幅：增幅效果 +100%，范围缩成十字 | 要改增幅范围判定（`mod_buff_init` / 战斗管理器） | M/L |

### 4.10 起源（232）— S/M

缺：敌人死亡原因打标。
`Other_10` 里记 `hex_death_cause`（ash / bullet），`Destroy_0` 里按 `is_blown_away`（撞飞）、`crush_kill`（压扁）补齐；四种各触发过一次 → 全队 +20%（最多 +80%）。

### 4.11 宝石三件套（235 / 236 / 237）— M

缺：统一的宝石冷却出口。
17 个宝石对象的 `Create_0` 都是 `cooldown = gem_info.cooldown[level] * 60`，脚本批量改成 `* hex_gem_cooldown_mult()`（0.9 / 0.8 / 0.5）。
"常驻增幅类改为效果加强"需要一张宝石分类表（哪些是常驻增幅），可以先只做冷却那一半。

### 4.12 海洋的婚礼（246）— M

缺："海底旋涡美食"的定义 + 免窒息钩子。
建议定义成"带 `drown_timer` 的 7 张海底卡"（`obj_coal_starfish` 等），加 `hex_no_drown()` 在每个卡的窒息判定里短路。
"海神 + 海洋女神同时携带"用 `global.selected_deck` 查 id；鼠军每秒 -1% 上限走 `hex_periodic_run`。

### 4.13 这不是外挂（249）— S

缺：卡片"穿透"字段。
用分类名判定（`直线穿透类` / `过火穿透类`）或子弹 `damage_type == "pierce"`；火苗获取 -50% 走已有的 `flame_growth` 通道。

### 4.14 低语耳环（254）— L

缺：跨存档永久成长 + 卡组随机化 + "皇冠关"标记。
- 每局结束提升卡片等级：直接改 `save_data` 里的卡片星级，注意各岛上限（美味 6 / 火山 9 / 浮空 13）；
- 进关无法自选卡：拦卡组选择，从 `unlocked_cards` 随机抽，保底各分类各一张；
- "皇冠关"没有字段，建议用"该关有 BOSS 波"替代。

这条是 68 条里唯一动到**存档结构**的，建议单独排期，且先只做"随机卡组"那一半（简单、体感明显）。

## 8. 一句话给决策

68 条里 **47 条今天就能写**、**19 条要先补一层薄机制**、**只有 2 条纯资源/架构卡住**（帧伤、全屏视频）。

真正需要你拍板的不是"能不能做"，而是三件事：
1. 编号与重名（184 占用、254 与 184 同名）；
2. 几个没落点的定义（皇冠关、海底旋涡美食、卡片防碾压）；
3. 数值——`3^16` 倍血量、每 10 秒杀一张卡、每只鼠掉 100 金币，这三条按字面实现会直接破坏现有平衡。
