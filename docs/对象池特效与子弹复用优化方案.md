# 对象池特效与子弹复用优化方案

**日期：2026-11-10**

---

## 一、对象池现状

### 1.1 拦截方式（全局宏替换）

`scripts/src_hook_function/src_hook_function.gml`：

```gml
#macro instance_create_depth_origfunc instance_create_depth
#macro instance_create_depth          instance_create_depth_define

#macro instance_destroy_origfunc instance_destroy
#macro instance_destroy          obj_pool_instance_destroy
```

**全项目的 `instance_create_depth` / `instance_destroy` 都被替换了**。所以哪怕代码里写的是原生函数名，实际也走池。

### 1.2 池化白名单（`obj_pool_is_poolable`，`obj_pool.gml:52-73`）

| 判定方式 | 命中对象 |
|---|---|
| 对象名含 `bullet` | 全部子弹（184 个） |
| 对象名含 `explode` | 爆炸类 |
| 对象名含 `ash_death` | `obj_mouse_ash_death` / `_1` / `_2` / `_3` / `_4` |
| 对象名含 `death_effect` | `obj_drop_death_effect` |
| `obj_zodiac_projectile` | 星座弹道 |
| 敌人白名单 | 20 个基础鼠类 |

### 1.3 复用流程（`obj_pool_acquire`，`obj_pool.gml:97-140`）

```gml
with (_inst) {
    x = _x;
    y = _y;
    depth = _depth;
    visible = true;
    instance_change(_obj, true);          // ← 重跑新对象的 Create
    event_user(14);

    if (obj_pool_is_enemy_whitelisted(_obj)) {   // ← 只有敌人重置显示属性
        image_alpha = 1;
        image_blend = c_white;
        image_index = 0;
        image_speed = 0;
        image_angle = 0;
        flash_value = 0;
        visible = true;
    }
}
return _inst;
```

**关键问题：只有敌人分支重置了显示属性，子弹和特效都没有。**

### 1.4 回收流程（`obj_pool_release`，`obj_pool.gml:142-193`）

```gml
with (_inst) {
    instance_change(obj_pool_holder, true);   // ← 触发旧对象的 Destroy
    visible = false;
    x = -100000; y = -100000; depth = 100000;
}
```

`obj_pool_holder` 的 `spriteId` 是 `null`，所以释放后实例的 `sprite_index` 变成 `-1`。**实例变量（`image_alpha` / `image_angle` / `image_index` / `bounced` 等）全部保留**，这就是复用时"带记忆"的根源。

## 二、问题一：被布丁反弹的子弹复用后反向

### 2.1 反弹怎么实现的

以 `obj_corn_shooter_bullet/Collision_obj_cherry_pudding.gml` 为例：

```gml
if (!bounced && row == other.grid_row)
{
    move_speed *= -1;          // 速度取反
    bullet_rebound_bonus(id, other.atk);
    image_angle += 180;        // ← 贴图翻转 180°
    bounced = true;
}
```

### 2.2 复用后为什么是反的

`obj_corn_shooter_bullet/Create_0.gml` 全文：

```gml
damage = 0;
move_speed = 0;        // ← 有重置（创建者随后赋正值）
row = 0;
damage_type = "normal";
target_type = "normal";
burnt = 0;
bounced = false;       // ← 有重置
brazier_list = ds_list_create();
image_xscale = 1.8;
image_yscale = 1.8;
hittable_types = get_hittable_enemy_types(target_type);
hit_tick = 0;
```

**没有 `image_angle = 0`。**

所以复用后：
- `move_speed` 被重置成正数 → **运动方向是对的**（向右飞）
- `image_angle` 残留 `180` → **贴图是上下颠倒的**

观感就是"射出反向子弹"。同理 `image_blend` 若残留（比如被冰冻染成蓝色），复用后颜色也不对。

### 2.3 波及范围（实测）

扫了 184 个名字含 `bullet` / `projectile` 的对象：

| 缺失项 | 数量 |
|---|---|
| 未初始化 `image_angle` | **137 / 184** |
| 未初始化 `image_index` | 156 / 184 |
| 未初始化 `image_alpha` | 155 / 184 |

已经有 47 个写了 `image_angle`（多是玫瑰盾这类需要随方向旋转的），其余全裸。

## 三、问题二：灰烬特效时不时消失

### 3.1 不是池子不够

`obj_pool_release` 第 186 行：

```gml
if (ds_list_size(_list) >= global._obj_pool_limit) {
    _st.drop++;
    instance_destroy_origfunc(_inst);   // 超上限 → 真销毁
    return;
}
```

池上限 256，超了就是**真销毁再重建**，只会多一次 Create，**不会导致"特效不出来"**。

### 3.2 真正原因：三个显示属性全部残留

`obj_mouse_ash_death/Create_0.gml` 全文：

```gml
sprite_index = spr_mouse_ash_death;   // ← 有（因为 holder 会把 sprite_index 置 -1）
image_xscale = 1.8
image_yscale = 1.8
image_speed = 0
timer = 0          // ← 淡出计数，初值应该是 10
life = 90
can_destroy = false
special_ash = false
hit_shader = hit_effect_2
```

**没有 `image_index` / `image_alpha` / `image_angle`。**

而 `Step_0.gml` 的销毁段：

```gml
if can_destroy{
    if not special_ash{
        image_index = 14;      // ← 停在第 14 帧（可能是空白帧）
    }
    image_speed = 0
    timer--;                   // ← 0 → -1
    image_alpha = timer / 10;  // ← -1/10 = -0.1
    if timer < 0 {
        instance_destroy()     // ← 一帧就销毁
    }
}
```

**两个独立缺陷叠加**：

1. **`timer` 初值错**：`timer = 0` 而不是 `10`。`timer--` 之后立刻是 `-1`，`timer < 0` 成立，**淡出阶段只跑 1 帧**，alpha 从 -0.1 直接销毁。本来应该是 10 帧从 1.0 淡到 0.0
2. **`image_index` / `image_alpha` 残留**：上次销毁时 `image_index` 被设成 14、`image_alpha` 被设成 ≈0。复用后 Create 不重置 → **新特效从第 14 帧开始播，且完全透明**

### 3.3 为什么"时不时才有"

池里同时有多个 `obj_mouse_ash_death` 实例，状态依赖**上一次的生命周期**：

| 上一次怎么死的 | 复用后的状态 | 表现 |
|---|---|---|
| 走到 `can_destroy`（正常淡出） | `image_index = 14`、`image_alpha` ≈ 0 | **完全看不见** |
| 被 `drop` 真销毁（池满） | 新建实例，alpha = 1 | 正常显示 |
| 敌方 `special_ash` 分支 | `image_speed = 0` 残留 | 不播动画，静止 |

所以大范围秒杀（光明神圣光这类一次几百个）最容易撞上——池里全是"上次淡出过"的脏实例。

### 3.4 `_1..4` 的额外问题

`obj_mouse_ash_death_1` 到 `_4` 的 Create **连 `sprite_index` 都没写**：

```
obj_mouse_ash_death    | sprite_index=spr_mouse_ash_death  image_index=缺  image_alpha=缺  timer=0
obj_mouse_ash_death_1  | sprite_index=缺                   image_index=缺  image_alpha=缺  timer=0
obj_mouse_ash_death_2  | sprite_index=缺                   image_index=缺  image_alpha=缺  timer=0
obj_mouse_ash_death_3  | sprite_index=缺                   image_index=缺  image_alpha=缺  timer=0
obj_mouse_ash_death_4  | sprite_index=缺                   image_index=缺  image_alpha=缺  timer=0
```

主对象有 `Step_0` 兜底（`if (!sprite_exists(sprite_index)) sprite_index = spr_mouse_ash_death;`），`_1..4` 没有。

## 四、方案

### 方案 A（推荐）：在 `obj_pool_acquire` 统一重置显示属性

改一处，覆盖全部 184 个子弹 + 5 个灰烬 + 爆炸类。

`obj_pool.gml:121-138` 改成：

```gml
_st.get++;
with (_inst) {
    x = _x;
    y = _y;
    depth = _depth;
    visible = true;

    // ── 复用前清空上一个宿主留下的显示状态（必须在 instance_change 之前）──
    //  Create 里显式赋值的会覆盖这里，Create 没写的就用这套默认值兜底。
    image_angle  = 0;
    image_alpha  = 1;
    image_blend  = c_white;
    image_index  = 0;
    image_speed  = 0;

    instance_change(_obj, true);   // ← 重跑 Create
    event_user(14);

    if (obj_pool_is_enemy_whitelisted(_obj)) {
        image_alpha = 1;
        image_blend = c_white;
        image_index = 0;
        image_speed = 0;
        image_angle = 0;
        flash_value = 0;
        visible = true;
    }
}
```

**为什么必须放在 `instance_change` 之前**：

`instance_change` 会执行新对象的 Create，Create 里写的 `image_xscale = 1.8`、`image_index = 0`、`image_speed = 0` 才是对象想要的最终值。如果放在之后，会把 Create 刚设好的值冲掉（比如 `obj_mouse_ash_death` 的 `image_index` 会被重置，但它本来也不设，无影响；而 `obj_rig_bullet` 的 `image_index` 由 Step 每帧算，无影响）。

**风险点**：

1. `image_speed = 0` 会不会让某些靠引擎自动播放的动画停掉？
   —— 不会。这类对象都在 Create 里显式写了 `image_speed = 1` 或 Step 里每帧赋，Create 会覆盖
2. `image_angle = 0` 会不会破坏玫瑰盾这类需要初始角度的？
   —— 不会。它们的创建者会在 `instance_create_depth_define` 返回后赋 `image_angle`，那是之后的事
3. 有没有对象依赖"复用后保留 image_angle"？
   —— 没有。这类是 bug 不是特性

### 方案 B：逐个对象补 Create

给 137 个子弹 + 5 个灰烬各加三行重置。

- 优点：显式、可控
- 缺点：184 个文件，以后新增对象或复制粘贴时必然漏；改一次要跑一遍全量扫描

**不推荐**：这是典型的"应该在框架层解决"的问题。

### 方案 C：只修灰烬，子弹不动

治不了反弹反向的问题。

## 五、配套修复（方案 A 之外还必须做的）

### 5.1 `timer` 初值（这是"直接消失"的直接原因）

`obj_mouse_ash_death/Create_0.gml` 第 12 行、`_1..4` 同位置：

```gml
timer = 0;    →    timer = 10;
```

改完淡出段才是设计意图：10 帧内 `image_alpha` 从 1.0 线性降到 0.0。

### 5.2 给 `_1..4` 补 `sprite_index`

```gml
sprite_index = spr_mouse_ash_death;
```

（它们的 `.yy` 里 `spriteId` 本来就指向 `spr_mouse_ash_death`，但 `instance_change` 从 holder 切换回来时不一定恢复，主对象已经踩过这个坑，注释里写得很清楚。）

### 5.3 `special_ash` 分支的 alpha

`Step_0` 里 `can_destroy` 分支在 `special_ash = true` 时也要走淡出，否则特效会停住不动直到 `timer` 耗尽。现有代码 `image_alpha = timer / 10` 是对的，只要 `timer` 初值改对就正常。

## 六、验证方式

### 6.1 反弹方向

1. 用能打直线子弹的卡（玉米、彩虹蛇、热狗）打有布丁的关卡
2. 让子弹被反弹
3. 观察反弹后被复用的同款子弹：**应全部朝右飞、贴图正向**

### 6.2 灰烬特效

1. 用光明神圣光这类大范围秒杀
2. 连续放 5～10 次
3. 观察灰烬：**每一次都应该完整播出 90 帧 + 10 帧淡出**
4. 池统计 `global._obj_pool_stats` 里 `drop` 不应暴涨

### 6.3 回归检查

- 玫瑰盾 / 星辰类子弹（依赖 `image_angle`）：方向正确
- 冰系子弹（`image_blend` 染色）：颜色正确
- 敌人池化（原有分支）：无变化
