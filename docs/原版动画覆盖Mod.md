# 原版动画覆盖 Mod v1

此扩展在绘制原有对象时使用外部 PNG 序列，不替换工程中的精灵资源，也不注册新对象。
实例的 `sprite_index`、`image_index`、`mask_index`、动画区间、攻击/生产计时和存档数据保持原样。
原版逻辑帧内的进度映射到补帧序列，因此可以改善动画观感而不改变移动、出弹、产火和伤害时机。

Mod 包由原尺寸 PNG 序列和 JSON 配置组成，素材可以使用任意工具制作，接入格式见下文。

## 支持范围

- 已有卡片、敌鼠、子弹、精灵型独立特效和玩家角色。
- 共用父类绘制、自定义 Draw 事件中的标准精灵绘制，以及原本依赖引擎默认绘制的多帧精灵对象。
- 按原精灵名称和对象限定覆盖；形态、换装切换到另一个精灵后，独立查找对应覆盖项。
- 可以只覆盖部分动作或部分形态。未覆盖的帧、精灵和对象自动使用原版图片。
- 保留原点、像素尺寸、旋转/镜像/缩放、裁剪、受击闪白、减速染色、透明度和各类叠层。
- 导入、开关和删除复用设置里的 Mod 管理界面，完全退出并重启游戏后生效。
- 关闭或移除覆盖包后恢复原版显示，不影响卡片养成进度。

不同类别和动作可以使用不同动画时钟。对自行计算整数帧号的对象，需要声明原计时器及换帧周期；
不能只选择 `image_index` 后就假定有帧内进度。没有 PNG 的程序化特效、自定义顶点绘制和
预先画入 surface 的缓存图像，不会自动变成 PNG 动画覆盖。

## 包格式

使用 ZIP，可以改扩展名为 `.fvmmod`。包根目录放 `manifest.json`，兼容一层外目录。
不需要 `card.json` 或 `logic.lua`。

```json
{
  "api_version": 1,
  "type": "animation_override",
  "name": "我的原版动画覆盖",
  "overrides": ["small_fire.json"]
}
```

每个覆盖配置对应一个原精灵。以下为可用的单帧覆盖格式示例；图片需要自行提供：

```json
{
  "sprite": "spr_small_fire",
  "object": "obj_small_fire",
  "clock": "card_parent",
  "source": {
    "frames": 29,
    "width": 49,
    "height": 112,
    "origin_x": 24,
    "origin_y": 112
  },
  "clips": [
    {
      "name": "idle",
      "first": 0,
      "last": 0,
      "samples_per_frame": 1,
      "loop": false,
      "frames": ["images/idle_00001.png"]
    }
  ]
}
```

完整补帧包应按动作分段。例如小火炉待机是原帧 `0..11`，产火是 `12..28`。
每个原帧配 6 张样本时，分别提供 72 和 102 张 PNG，总计 174 张。
`first/last` 都是从零开始且包含端点，不能重叠；`frames` 的顺序就是采样顺序。
PNG 路径相对于该覆盖配置文件所在目录，仅允许包内相对路径。

| 字段 | 含义 |
|---|---|
| `sprite` | 已编译原精灵的资源名称，不是文件路径或卡片 ID |
| `object` | 目标对象名称，覆盖该对象及其子类，避免同精灵的其他用户被误替换 |
| `source` | 原精灵帧数、尺寸及原点，导入和启动时必须与当前游戏一致 |
| `clock` | 时钟名称或配置对象，可在每个动作段内单独指定；未指定时按对象类别选择默认值 |
| `samples_per_frame` | 每个原帧的视觉样本数，整数 1–16，与 PNG 数量相匹配 |
| `loop` | 素材制作时该动作是否首尾闭合，不控制游戏状态机 |
| `source_sha256` | 外部工具可写入用于追溯；运行时只校验 `source` 的结构元数据，不验证像素哈希 |

所有 PNG 必须与原精灵像素尺寸完全相同。覆盖原点直接继承原精灵，不能按新的可见区域重新定位。
每包最多 128 个精灵、每个精灵 32 段、每段 4096 张 PNG，估算 RGBA 数据每包最多 256 MiB。
同一个精灵不能在包内重复声明，也不能与其他已安装覆盖包冲突，包括关闭状态的已安装包。
不写 `type` 的旧卡片包继续按原有卡片 API v1 加载。

## 时钟与动作边界

`card_parent` 使用卡片父对象或玩家角色推进动画时记录的原帧号、状态、计时器和实际换帧周期。
例如原来一张图片停留 6 步，补帧后在这 6 步内显示 6 张样本，原帧号保持不变。
减速后的 12 步会相应拉长显示时间。暂停或冻结使原时钟停止，Draw 不另外推进时间；
倍速沿用对象本身的动画规则。子类更改帧号、状态或精灵后，旧的帧内进度失效，先显示对应关键帧。

`enemy_parent` 使用原有 `timer / flash_speed` 的小数部分，适用于标准敌鼠的行走、攻击和死亡动画。
护甲破损、状态切换、上梯位移等继续由原状态机决定。特殊 Boss、独立动画控制器应明确指定自己的时钟。

`image_index` 使用原 `image_index` 的小数部分作为进度。适用于原本就采用小数帧号的自定义播放。
若原帧号始终为整数，此模式仅显示对应关键帧，无法自行推断下一帧时间。
卡片及玩家默认选择 `card_parent`，敌鼠默认选择 `enemy_parent`，其他对象默认选择 `image_index`。

对于 `image_index = floor(timer / 3)` 一类播放方式，用 `counter` 声明原计时器，不改变该计时器：

```json
"clock": {"type": "counter", "field": "timer", "ticks_per_frame": 3}
```

若换帧周期也存放在实例变量中，可以改用 `period_field`：

```json
"clock": {"type": "counter", "field": "anim_timer", "period_field": "flash_speed"}
```

对于先累加小数相位、再取整设置帧号的控制器，例如龙渊的 `ly_frame`，使用 `phase`：

```json
"clock": {"type": "phase", "field": "ly_frame"}
```

`counter` 读取 `(field + offset) / 周期` 的小数部分，`phase` 读取 `field + offset` 的小数部分。
`offset` 默认为 0，可对齐计时器在设置帧号前后自增的差异。`period_field` 优先于 `ticks_per_frame`，
动态周期必须大于零。变量缺失或数值无效会报告错误并回退原版，不会修改对象或执行配置中的代码。

如果计时器递增而原帧号倒序播放，可添加 `direction: -1`，从前一原帧的补帧区间逆向采样。
循环动作允许跨首尾连接，单次动作到第一帧后保持。原本就有小数帧号的倒放通常直接使用 `image_index`。

每个 `clips` 条目都可覆盖顶层 `clock`，用于同一精灵内具有不同速度、计时器或播放方向的动作。
正常 60 步游戏下，10fps 动作每原帧 6 个样本、12fps 动作每原帧 5 个样本即可达到 60fps 观感；
不同源帧率可以在同一包中共存。精灵编辑器的预览帧率不一定等于运行时的实际换帧规则。

动作边界必须在离线处理时正确制作：循环段最后接该段首帧，单次段最后复制该段末帧定格。
不要把整张精灵的待机、攻击等不同动作连在一起补帧。原帧数和硬编码区间可能存在历史差异，
配置必须以精灵实际可用帧为准，例如 29 帧精灵的最后一帧是 28。
**覆盖包不需要更改 `flash_speed`、`idle_anim` 或 `attack_anim`。**

## 绘制接入

项目的 `draw_self`、`draw_sprite`、`draw_sprite_ext`、`draw_sprite_part` 和 `draw_sprite_part_ext`
通过保留原生别名的统一入口选择覆盖帧，再原样传递位置、变换、颜色、透明度和裁剪参数。
辅助精灵也按当前绘制对象和传入的精灵/帧号匹配，所以多层敌鼠、玩家换装和裁剪绘制不需要改战斗代码。
未启用任何覆盖包时直接调用原生绘制。没有匹配覆盖项、对象不在作用范围内或调用者为 struct 方法时，
保留原来的绘制结果，不把 UI 或其他对象误识别为目标对象。

原本使用引擎默认绘制的多帧精灵对象增加了等价的 `draw_self()` Draw 入口，包括子弹、独立特效、
武器、地图物件及菜单元素；运行时才设置精灵的镰刀和米线特效也提供同样的入口。
原来用空 Draw 事件主动隐藏的对象保持隐藏，包括声明了 Draw 事件但没有代码文件的情况。
入口必须同时在对象 `.yy` 的 `eventList` 中声明普通 Draw 事件（`eventType: 8`、`eventNum: 0`），
仅放置 `Draw_0.gml` 文件不会执行。以后新增这种精灵对象时，也需要提供这个入口或继承已接入的父对象；
自行推进整数帧号的对象仍需按上文配置动画时钟。

## 加载、释放与失败回退

启动时解析覆盖索引并检查 PNG 文件头与尺寸，不为覆盖包加载 Lua 或创建纹理。
首次显示某个动作时解码其 PNG 并组成运行时精灵，同一动作的多个卡片实例共享缓存；
加载时使用的临时精灵在合并后立即删除。首次显示可能产生一次加载开销。
切换房间或销毁管理器时释放覆盖纹理，下一场景按需重新加载。
缓存估算 RGBA 数据上限为 256 MiB，实际 CPU/GPU 内存还受引擎纹理分配影响。

版本不匹配、无效 PNG、缺图、重复覆盖等会产生可在 Mod 管理界面查看的错误。
解码失败或缓存超限时释放该包已分配的覆盖纹理，并回退原版显示，避免每帧重复报错。
