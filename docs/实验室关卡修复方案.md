# 实验室关卡修复方案

> 目标工程：`D:\gameProject\FVM-Reborn-mod`（MAKK 版，GM 3.0.2.7）
> 参照工程：`D:\gameProject\FVM-Reb-OnlineVersion-main`（在线版主体）
> 结论一句话：**实验室的"地图关卡"断在「地图插件脚本 VM」这一层——`.bin` 从来没有被加载过，因为 VM 运行时、编译工具、事件挂载点三者本项目全缺；与 DLL / 插件文件无关。** 次要问题在加载校验过严与缓存目录污染。

---

## 0. TL;DR

| 现象 | 根因 | 处置章节 |
|---|---|---|
| 实验室里某些图根本不出现 | `verify_stage` 强制四资源（精灵 + 三首音乐）齐全，缺一即整关丢弃；错误只弹一次提示 + 写剪贴板，没有逐关定位 | §4.5 |
| 图能进，但"机关不动 / 平台不出现 / 不出怪 / 禁卡不生效" | `StageDetail.on_create_room()` 从不读同名 `.bin`，全项目 0 处 `VM_` 符号，地图脚本 100% 不执行 | §4.1–§4.4 |
| 玩家自己写不出 `.bin` | `datafiles` 里没有 `LabMapCompiler.exe`、没有可视化编辑器、没有样例脚本 | §4.6 |
| 联机下载的地图重复出现 / 被当关卡 | 缺 `is_online_cache_path()`，`laboratory/cache/` 下的缓存 json 被当关卡加载 | §4.5 |
| 进了图但音乐/背景图丢失 | 资源解析只走 `asset_get_index`，无懒加载回退；旧的 `FVM_Reborn` 目录与新 `FVM_Reborn_makk` 目录混用 | §4.5 |

工程量：**地图脚本链完整移植 ≈ 3–5 人天**（含验收），只做本地加载健壮性 ≈ 0.5 人天。

## 2. 断点定位（5 条，带证据）

### D1 — `.bin` 从不加载（最高优先级）

参照版 `objects/StageDetail/Create_0.gml:86-97`：

```gml
var _json_dir = self.state.custom_stage.json_path;
global._file_cache_json_path = _json_dir;
var _bin_buf = undefined;
var _bin_path = string_replace(_json_dir, ".json", ".bin");   // ★ 同名同目录
global._sync_vm_seed = irandom(2147483646) + 1;
global.__vm.rng_state = global._sync_vm_seed;
if (file_exists(_bin_path)) {
    _bin_buf = buffer_load(_bin_path);
    VM_InitRoomEntry(_bin_buf);
    buffer_delete(_bin_buf);
} else {
    VM_InitRoomEntry(undefined);
}
```

本项目 `objects/StageDetail/Create_0.gml:69-83` 的 `on_create_room()` **完全没有这一段**，直接 `global.gui_stack.to(room_ready)`。

### D2 — 解释器整体不存在

`grep -r "VM_" FVM-Reborn-mod/{scripts,objects}` = **0 命中**；同时 `datafiles` 下 **0 个 `.bin`**。
参照版 `_VM_` 符号命中 **335 处 / 62 个文件**。

### D3 — 编译器未随包

参照版 `datafiles` 顶层：`LabMapCompiler.exe`、`mod和地图插件脚本编辑工具.exe`、`联机中继器.exe`、`联机教程.pdf`、`mod_enable.txt`、`connection_enable.txt`、`mod/`、`mod开发文档/`、`地图插件脚本工具demo/`。
本项目 `datafiles` 顶层只有：`laboratory/`、`level_data/`、`native/`、`scribble_license.txt`。

### D4 — 校验过严 + 无逐关错误

`scripts/LaboratoryTypedef/LaboratoryTypedef.gml:290-303`：

```gml
if (stage.map_sprite == -1)  → INVALID_METADATA（fail）
if (stage.pre_music == -1)   → fail
if (stage.elite_music == -1) → fail
if (stage.boss_music == -1)  → fail
```

失败仅 `LaboratoryGUI/Create_0.gml:86-89` 弹一次 `show_message_async("加载某些关卡出现问题，日志已经复制到剪贴板中")` + `clipboard_set_text(_result.message)`。
→ 玩家写图时漏填 `boss_music` 这种字段，整张图直接消失，且不知道是哪张。

### D5 — 缓存目录污染 / 路径迁移 / 资源解析口径

1. `LaboratoryManager.load_all_stages()` 递归收集 `laboratory/**/*.json`，**没有跳过 `laboratory/cache/`**；参照版有 `is_online_cache_path()` 判断并在循环里 `continue`。
2. 本项目 `get_audio_or_create` / `get_sprite_or_create` 只走 `asset_get_index`；参照版失败后回退 `get_load_audio` / `get_load_sprite`（懒加载，依赖 `global._audio_reverse` / `_pid_reverse`）——**这两个函数本项目不存在（0 命中），移植时不许连带拷**。
3. 关卡 id 用完整路径（`create_custom_stage`: `id = _json_path`），会写进 `global.level_id`；`obj_event_manager/Step_0.gml` 前 365 行的 `level_id == "tower-1-1"` 这类硬编码自然全部不命中（对自定义图是对的），但 `battle_finish_win` 等按 id 分支的地方需要回归确认。

| `obj_Bullet_Screen_Management` | 屏内子弹管理（VM 判定用） | 本项目无 → 用 `instance_number(obj_bullet_parent)` 之类替代，或补一个空对象 |

#### 1.3 `src_mod` 的挂载点函数

参照版 `scripts/scr_command_VM/scr_command_VM.gml:3574-3578` 定义了 `vm_hook_run(_name)`，而 `src_mod` 提供 mod 侧注册/分发。本项目只有地图脚本，没有 mod 单位，因此二选一：

- **方案 A1（省事）**：保留 `src_mod`，但把 `vm_hook_run()` 改成空壳（返回 undefined），删掉 `src_mod` 里依赖 `obj_*_mod` 的部分；所有 `vm_hook_run("_VM_XXX")` 调用点保留但空转。
- **方案 A2（更干净）**：不拷 `src_mod`，直接删掉所有 `vm_hook_run(...)` 行（见 Phase 4 列表里带 `// mod 侧` 注释的那一半）。

**推荐 A2**：本项目已有自己的 Lua Mod 体系，双轨只会增加维护面。代价是未来想接"地图脚本 mod 化"要重做。

### Phase 2 — VM 句柄初始化

参照版 `objects/obj_game_init/Other_2.gml:18` 有 `global._vm = VM_Create();`，但**全工程没有任何地方把 `global._vm` 赋给 `global.__vm`**（`VM_InitRoomEntry` 内部却大量使用 `global.__vm`）——这是参照版的一处历史遗留，移植时必须显式对齐，否则第一次进图就是 `Variable global.__vm not set`。

在本项目 `objects/obj_game_init/Other_2.gml` 的注册序列里（建议紧跟 `maps_init()` 之后，与参照版同位置）插入：

```gml
// —— 地图插件脚本 VM（实验室 / 后续自定义关）——
global.__vm = VM_Create(65536);
global._vm  = global.__vm;                 // 兼容参照版命名，二者同体
global.__vm.rng_state = 0x9E3779B9;
global._VM_hooks            = ds_map_create();
global._VM_sprite_temp_cache= ds_map_create();
global._VM_id_to_real       = ds_map_create();
global._VM_real_to_vm_id    = ds_map_create();
global._VM_dead_snaps       = ds_map_create();
global._VM_loaded_sprite_indices = [];
global._VM_hook_queue       = [];
global.banned_cards_online  = ds_map_create();
global.banned_gems_online   = [];
```

> 这些全局在 `VM_InitRoomEntry()` 里会被重置，但**第一次**进图前必须存在（函数第一行就 `ds_map_clear(global.banned_cards_online)`）。放在 `obj_game_init/Other_2.gml` 而不是 `obj_game_init/Create_0.gml`，是为了跟现有注册顺序保持一致、避免被 `load_file()` 覆盖流程影响。

### Phase 3 — StageDetail 接入

改 `objects/StageDetail/Create_0.gml` 的 `on_create_room()`（当前 69-83 行），替换为：

```gml
function on_create_room() {
    if (is_undefined(self.state.custom_stage)) return

    var _json_path = self.state.custom_stage.json_path
    var _parse_result = global.laboratory_manager.file_util.load_json_from_path(_json_path)
    if (_parse_result.is_failed()) throw _parse_result.get_error_stack()

    // ── 地图插件脚本（同名 .bin，可选）───────────────────────────
    var _bin_path = string_replace(_json_path, ".json", ".bin")
    var _has_bin  = file_exists(_bin_path)
    if (_has_bin) {
        var _bin_buf = buffer_load(_bin_path)
        VM_InitRoomEntry(_bin_buf)
        buffer_delete(_bin_buf)
    } else {
        VM_InitRoomEntry(undefined)   // 必须调用：负责重置上一关残留的 _VM_* 状态
    }
    // ────────────────────────────────────────────────────────────

    global.level_data = level_entry_from_stage_metadata(self.state.custom_stage)
    global.level_id   = self.state.custom_stage.id
    global.level_file = _parse_result.data
    global.gui_stack.to(room_ready)
    window_set_cursor(cr_arrow)
}
```

必读的三条约束：

1. **`VM_InitRoomEntry(undefined)` 不能省**。它负责清掉上一关留下的 `global._VM_*`（含 `blocks` ds_map 里的 buffer，不释放会泄漏）。
2. `_json_path` 必须是**实际存在的磁盘路径**（`file_exists` 语义）；`stage.json_path` 在本项目就是绝对路径，可直接用。
3. `global.__vm.rng_state` 若要做"同种子复现"，在 `VM_InitRoomEntry` 前赋值；单机实验室不强求，先不做。

同样的接入点还有 2 处（参照版有、本项目没有），用于从选关页直接进自定义图：

- `objects/obj_levelselect_button/*`（1 处）
- `objects/obj_tower_cake_start_btn/*`（1 处）

## 7. 风险与回滚

| 风险 | 说明 | 缓解 |
|---|---|---|
| VM 栈引入后帧率下降 | `_VM_FRAME` 每帧派发 5 个 timer 检查 + 块执行 | bin 为空时 `buffer_exists` 提前返回；只在 `_VM_FRAME` 块存在时才跑 |
| 全局命名冲突 | `global.__vm` / `_VM_*` 与海克斯 `hex_*` 无交集，但 `global.banned_cards_online` 与现有禁卡逻辑（`cards_init`）可能重叠 | 先 grep `banned_cards_online` 是否已被本项目使用，若无则随 VM 一起引入 |
| `VM_InitRoomEntry` 依赖的 ds_map 未初始化 | 首次进图 `ds_map_clear` 直接崩 | Phase 2 的初始化块必须一起上 |
| 关卡 id 全路径污染存档 | 通关记录写入 completed_levels | Phase 5 第 4 点 |
| 编译器 exe 被安全软件拦 | 未签名可执行文件 | 说明文档注明，或放 Release 由玩家手动放 |

回滚：`git checkout main -- .` 或恢复 `FVM_Reborn_makk.yyp.labbak`；因为改动集中在 4 个新脚本目录 + 5 个对象的少量插入，回滚成本低。
